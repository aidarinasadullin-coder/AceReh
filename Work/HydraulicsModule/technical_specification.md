**Проект:** Калькулятор снеготаяния РЕХАУ  
**Версия ТЗ:** 2.0  
**Дата:** 2026-03-17  
**Статус:** Новая версия (таблица контуров, две температуры)

## 1. Общее описание

### 1.1. Краткое описание задачи

Модуль "Контура" предназначен для гидравлического расчёта **таблицы контуров** систем снеготаяния РЕХАУ. Модуль обеспечивает расчёт до 48 контуров (4 коллектора × 12 контуров) с поддержкой **двух температурных режимов**: рабочая температура и расчётная температура (холодный пуск).

**Начальное состояние UI:**
- По умолчанию отображается **1 коллектор с 4 контурами**
- Кнопка **"+"** добавляет контура к коллектору (максимум 12 контуров на коллектор)
- Кнопка **"+ Коллектор"** добавляет новые коллекторы (максимум 4 коллектора)
- Кнопка **"–"** удаляет последний контур/коллектор
- Итого максимум: **4 коллектора × 12 контуров = 48 контуров**

### 1.2. Цель разработки

Создать модуль для:
1. Ввода и редактирования таблицы контуров (до 48 контуров)
2. Расчёта мощности каждого контура Q_HK по формуле РЕХАУ
3. Расчёта гидравлических параметров при **двух температурах**:
   - Рабочая температура: T_mean = (T_supply + T_return) / 2
   - Расчётная температура: t_cold (холодная пятидневка)
4. Балансировки контуров на коллекторе
5. Подбора коллекторов РЕХАУ (HKV-D, IV)
6. Интеграции с ThermalModule и ClimateModule

### 1.3. Ключевые отличия от предыдущей версии

| Параметр | Старая версия | Новая версия |
|----------|---------------|--------------|
| Количество контуров | 1 контур | До 48 контуров (4 коллектора × 12) |
| Температуры расчёта | Одна температура | Две температуры (рабочая и холодный пуск) |
| Модель данных | HydraulicParameters | CircuitRow + CircuitTemperatureResult |
| Результат | HydraulicResult | CircuitRow с OperatingResult и DesignResult |
| Коллекторы | Не учитывались | CollectorSummary для каждого коллектора |

### 1.4. Связь с существующей системой

**Входные данные из ThermalModule:**
- `PowerUp` (q_up, Вт/м²) — мощность вверх
- `PowerDown` (q_down, Вт/м²) — мощность вниз
- `SupplyTemperature` (T_supply, °C) — температура подачи
- `ReturnTemperature` (_return, °C) — температура обратки
- `SelectedPipe` — выбранная труба (D_ext, s, d_inner)
- `PipeSpacing` (VA_hk, мм) — шаг укладки

**Входные данные из ClimateModule:**
- `ColdFiveDayTemperature` (t_cold, °C) — температура холодной пятидневки

**Входные данные от пользователя:**
- Тип гликоля (этилен/пропилен)
- Концентрация гликоля (%)
- Длины контуров L_hk[] (м)
- Длины подводок L_zul[] (м)
- Шаг подводки VA_zul (см, по умолчанию 5)
- % q_zul (по умолчанию 10%)

### UC-01: Ввод параметров контуров (таблица)

#### 2.1. Название
Ввод и редактирование параметров контуров в таблице

#### 2.2. Актёры
- Пользователь (инженер-проектировщик)
- Система (Калькулятор РЕХАУ)
- ThermalModule (источник данных о мощности и температурах)

#### 2.3. Предусловия
1. Тепловой расчёт выполнен (ThermalCalculationResult.IsValid = true)
2. Климатические данные загружены (ClimateModule)
3. Труба выбрана в тепловом расчёте

#### 2.4. Основной сценарий
1. Пользователь открывает вкладку "Контура"
2. Система автоматически получает данные из ThermalModule:
   - Мощность вверх (q_up, Вт/м²)
   - Мощность вниз (q_down, Вт/м²)
   - Температура подачи (T_supply, °C)
   - Температура обратки (T_return, °C)
   - Тип трубы (D_ext, s, d_inner)
   - Шаг укладки (VA_hk, мм)
3. Система автоматически получает данные из ClimateModule:
   - Температура холодной пятидневки (t_cold, °C)
4. Пользователь вводит параметры теплоносителя:
   - Тип гликоля (этиленгликоль/пропиленгликоль)
   - Концентрация гликоля (10-90%)
5. Пользователь вводит параметры контуров в таблицу:
   - Номер контура (автонумерация)
   - Длина контура L_hk (м)
   - Длина подводки L_zul (м)
6. Система автоматически вычисляет:
   - Общую длину L_total = L_hk + L_zul
   - Площадь контура S = L_hk / (100 / VA_hk)
7. Пользователь может изменить параметры по умолчанию:
   - Шаг подводки VA_zul (по умолчанию 5 см)
   - Доля тепла от подводок q_zul (по умолчанию 10%)
8. Система отображает таблицу контуров с рассчитанными значениями

#### 2.5. Альтернативные сценарии
- **A1: Тепловой расчёт не выполнен** — система отображает предупреждение "Сначала выполните тепловой расчёт"
- **A2: Климатические данные не загружены** — система использует значение по умолчанию -30°C
- **A3: Добавление контура** — пользователь нажимает кнопку "Добавить контур"
- **A4: Удаление контура** — пользователь выбирает строку и нажимает "Удалить"
- **A5: Копирование параметров** — пользователь копирует параметры из предыдущего контура

#### 2.6. Постусловия
- Таблица контуров заполнена
- Параметры валидированы
- Данные готовы для расчёта

#### 2.7. Критерии приёмки

### UC-02: Расчёт мощности контура Q_HK

#### 2.1. Название
Расчёт тепловой мощности контура по формуле РЕХАУ

#### 2.2. Актёры
- Система (Калькулятор РЕХАУ)
- ThermalModule (источник q_up, q_down)

#### 2.3. Предусловия
1. Таблица контуров заполнена (UC-01)
2. Тепловой расчёт выполнен
3. Параметры контуров валидны

#### 2.4. Основной сценарий
1. Система получает из ThermalModule:
   - q_up (мощность вверх, Вт/м²)
   - q_down (мощность вниз, Вт/м²)
2. Для каждого контура система рассчитывает:
   - Площадь контура: S_контур = L_hk / (100 / VA_hk)
   - Площадь подводки: S_подводка = L_zul / (100 / VA_zul) ×(q_zul / 100)
   - Эффективная площадь: S_эфф = S_контур + S_подводка
3. Система рассчитывает мощность контура:
   ```
   Q_HK = [(L_hk / (100 / VA_hk)) + (L_zul / (100 / VA_zul)) × (q_zul / 100)] × (q_up + q_down)
   ```
4. Система отображает мощность для каждого контура в таблице

#### 2.5. Альтернативные сценарии
- **A1: q_up или q_down равны нулю** — система отображает предупреждение

#### 2.6. Постусловия
- Мощность Q_HK рассчитана для каждого контура
- Значения отображены в таблице

#### 2.7. Критерии приёмки
- ✅ Формула: Q_HK = [(L_hk/(100/VA_hk)) + (L_zul/(100/VA_zul))×(q_zul/100)] × (q_up + q_down)
- ✅ Единица измерения: Вт
- ✅ Точность: 1 Вт
- ✅ Расчёт для всех контуров в таблице

### UC-03: Расчёт при двух температурах

#### 2.1. Название
Расчёт гидравлических параметров при рабочей и расчётной температурах

#### 2.2. Актёры
- Пользователь (инженер-проектировщик)
- Система (Калькулятор РЕХАУ)
- ThermalModule (источник температур)
- ClimateModule (источник t_cold)

#### 2.3. Предусловия
1. Мощность Q_HK рассчитана (UC-02)
2. Тип и концентрация гликоля заданы
3. Труба выбрана (d_inner известен)

#### 2.4. Основной сценарий
1. Система определяет две температуры для расчёта:
   - **Рабочая температура**: T_operating = (T_supply + T_return) / 2
   - **Расчётная температура**: T_design = t_cold (холодная пятидневка)
2. Для каждой температуры система загружает свойства гликоля:
   - Плотность ρ (г/см³)
   - Кинематическая вязкость ν (мм²/с)
   - Теплоёмкость c_p (кДж/кг·К)
3. Для каждого контура система рассчитывает:
   - Расход: V_dot = Q_HK × 3.6 / (ρ × c_p × ΔT)
   - Скорость: v = V_dot × 4 / (3600 × π × d_inner²) × 10⁶
   - Число Рейнольдса: Re = 1000 × v × d_inner / ν
   - Режим течения (ламинарный/переходный/турбулентный)
   - Коэффициент трения λ
   - Удельные потери: R = 10000 × (v² × ρ × λ) / (2 × d_inner) × 100
4. Система сохраняет результаты в:
   - `CircuitRow.OperatingResult` — для рабочей температуры
   - `CircuitRow.DesignResult` — для расчётной температуры
5. Пользователь переключает режим отображения:
   - Переключатель "Рабочая температура" / "Расчётная температура"
   - Таблица отображает результаты для выбранного режима

#### 2.5. Альтернативные сценарии
- **A1: Свойства гликоля вне диапазона** — система интерполирует/экстраполирует
- **A2: Переходный режим течения** — система отображает предупреждение

#### 2.6. Постусловия
- Результаты рассчитаны для обеих температур
- Пользователь может переключаться между режимами

#### 2.7. Критерии приёмки
- ✅ Расчёт для двух температур: рабочая и расчётная
- ✅ Переключатель режима отображения
- ✅ Свойства гликоля загружаются для каждой температуры
- ✅ Результаты сохраняются в CircuitTemperatureResult

### UC-04: Расчёт потерь давления

#### 2.1. Название
Расчёт потерь давления в трубах и вентилях

#### 2.2. Актёры
- Система (Калькулятор РЕХАУ)

#### 2.3. Предусловия
1. Гидравлические параметры рассчитаны (UC-03)
2. Тип коллектора определён (HKV-D или IV)

#### 2.4. Основной сценарий
1. Для каждого контура система рассчитывает потери в трубе:
   - Потери в контуре: Δp_HK = L_hk × R
   - Потери в подводке: Δp_Zul = L_zul × R
   - Общие потери в трубе: Δp_Rohr = Δp_HK + Δp_Zul
2. Система рассчитывает потери в вентиле:
   ```
   Δp_Vent = (V_dot / 1000 / Kv)² × 100000 × ρ
   ```
   где Kv зависит от типа коллектора:
   - HKV-D: Kv = 1.2 м³/ч
   - IV 1¼": Kv = 1.45 м³/ч
   - IV 1½": Kv = 1.5 м³/ч
3. Система рассчитывает суммарные потери:
   ```
   Δp_total = Δp_Rohr + Δp_Vent
   ```
4. Система отображает потери в таблице:
   - Δp_Rohr (Па)
   - Δp_Vent (Па)
   - Δp_total (Па и мбар)

#### 2.5. Альтернативные сценарии
- **A1: Потери превышают 320 мбар** — система отображает предупреждение

#### 2.6. Постусловия
- Потери давления рассчитаны для каждого контура
- Проверка ограничения 320 мбар

#### 2.7. Критерии приёмки
- ✅ Формула потерь в трубе: Δp = L × R
- ✅ Формула потерь в вентиле: Δp_Vent = (V_dot / 1000 / Kv)² × 100000 × ρ
- ✅ Проверка ограничения: Δp_total ≤ 320 мбар
- ✅ Расчёт для обеих температур

### UC-05: Балансировка контуров

#### 2.1. Название
Расчёт дросселирования и оборотов балансировочного клапана

#### 2.2. Актёры
- Пользователь (инженер-проектировщик)
- Система (Калькулятор РЕХАУ)

#### 2.3. Предусловия
1. Потери давления рассчитаны для всех контуров (UC-04)
2. Контур с максимальными потерями определён
3. Тип клапана выбран (HKV-D, IV 1¼", IV 1½")

#### 2.4. Основной сценарий
1. Система определяет контур с максимальными потерями (референсный контур):
   ```
   Δp_max = MAX(Δp_total для всех контуров)
   ```
2. Для каждого контура система рассчитывает дросселирование:
   ```
   zu_drosseln = Δp_max - Δp_total
   ```
3. Система определяет рекомендуемую настройку вентиля (1-8):
   - Настройка 1: минимальное сопротивление
   - Настройка 8: максимальное сопротивление
4. Система рассчитывает Kv для каждого контура:
   ```
   Kv = V_dot / 1000 / sqrt(Δp_Vent / (ρ × 100000))
   ```
5. Система рассчитывает обороты клапана по формулам:
   - **IV 1½"**: Обороты = 5.122 × Kv - 0.2106
   - **IV 1¼"**: Обороты = 5.1818 × Kv - 0.23
   - **HKV-D**: Обороты = 4.2111 × Kv³ - 6.7436 × Kv² + 4.6613 × Kv - 0.712
6. Система отображает в таблице:
   - Дросселирование (Па)
   - Рекомендуемая настройка вентиля (1-8)
   - Обороты клапана (с точностью до 0.1 оборота)
   - Признак референсного контура (★)
7. Пользователь может вручную изменить настройку вентиля

#### 2.5. Альтернативные сценарии
- **A1: Отрицательное дросселирование** — система устанавливает zu_drosseln = 0
- **A2: Дросселирование > 240 мбар** — система отображает предупреждение
- **A3: Kv < 0.5** — система отображает предупреждение о низкой точности
- **A4: Обороты < 0** — система отображает ошибку "Проверьте расчёт расхода"

#### 2.6. Постусловия
- Балансировка рассчитана для всех контуров
- Референсный контур отмечен
- Обороты клапана рассчитаны для каждого контура

#### 2.7. Критерии приёмки
- ✅ Формула: zu_drosseln = Δp_max - Δp_total
- ✅ Референсный контур: IsReferenceCircuit = true
- ✅ Настройка вентиля: 1-8
- ✅ Обороты клапана рассчитываются по формулам для каждого типа клапана
- ✅ Балансировка только для рабочей температуры

### UC-07: Интеграция с ThermalModule и ClimateModule

#### 2.1. Название
Получение данных из модулей теплового и климатического расчёта

#### 2.2. Актёры
- CircuitsViewModel (получатель)
- ThermalViewModel (отправитель)
- ClimateViewModel (отправитель)
- IThermalCalculationResult (интерфейс)
- IClimateData (интерфейс)

#### 2.3. Предусловия
1. Тепловой расчёт выполнен
2. Климатические данные загружены

#### 2.4. Основной сценарий
1. CircuitsViewModel подписывается на события:
   - `ThermalResultChanged` от ThermalViewModel
   - `ClimateDataChanged` от ClimateViewModel
2. При изменении теплового расчёта CircuitsViewModel получает:
   - `PowerUp` (q_up, Вт/м²)
   - `PowerDown` (q_down, Вт/м²)
   - `SupplyTemperature` (T_supply, °C)
   - `ReturnTemperature` (T_return, °C)
   - `SelectedPipe` (труба с d_inner)
   - `PipeSpacing` (VA_hk, мм)
3. При изменении климатических данных CircuitsViewModel получает:
   - `ColdFiveDayTemperature` (t_cold, °C)
4. CircuitsViewModel пересчитывает:
   - Рабочую температуру: T_operating = (T_supply + T_return) / 2
   - Расчётную температуру: T_design = t_cold
5. CircuitsViewModel обновляет отображение

#### 2.5. Альтернативные сценарии
- **A1: Тепловой расчёт невалиден** — система отображает ошибку
- **A2: Климатические данные отсутствуют** — система использует -30°C

#### 2.6. Постусловия
- Данные из ThermalModule и ClimateModule получены
- Гидравлический расчёт готов к выполнению

### UC-08: Управление контурами и коллекторами

#### 2.1. Название
Добавление и удаление контуров и коллекторов

#### 2.2. Актёры
- Пользователь (инженер-проектировщик)

#### 2.3. Предусловия
1. Вкладка "Контура" открыта
2. Тепловой расчёт выполнен

1. При открытии вкладки система отображает:
   - **1 коллектор** с **4 контурами** по умолчанию
   - Пустые строки для ввода длин контуров
2. Пользователь нажимает кнопку **"+"**:
   - Добавляется новый контур к текущему коллектору
   - Номер контура автоинкрементируется
   - Максимальное количество контуров на коллектор: **12**

   - Добавляется новый коллектор
   - К каждому коллектору привязывается таб/вкладка
   - Максимальное количество коллекторов: **4**
4. Пользователь нажимает кнопку **"–"**:
   - Удаляется последний контур текущего коллектора
   - Если контуров нет — удаляется последний коллектор
5. Система автоматически:
   - Нумерует контура в пределах коллектора
   - Пересчитывает итоги коллектора

#### 2.5. Альтернативные сценарии
- **A1: Достигнут лимит контуров (12)** — кнопка "+" неактивна, отображается подсказка
- **A2: Достигнут лимит коллекторов (4)** — кнопка "+ Коллектор" неактивна
- **A3: Попытка удалить последний контур** — подтверждение удаления
- **A4: Попытка удалить единственный коллектор** — система блокирует удаление

#### 2.6. Постусловия
- Таблица контуров обновлена
- Итоги коллектора пересчитаны
- Валидация выполнена

#### 2.7. Критерии приёмки

## 4. Формулы расчёта

### 4.1. Мощность контура

```
Q_HK = [(L_hk / (100 / VA_hk)) + (L_zul / (100 / VA_zul)) × (q_zul / 100)] × (q_up + q_down)  [Вт]

где:
- L_hk — длина контура, м
- VA_hk — шаг укладки, см
- L_zul — длина подводки, м
- VA_zul — шаг подводки, см (по умолчанию 5)
- q_zul — доля тепла от подводок, % (по умолчанию 10)
- q_up — мощность вверх, Вт/м²
- q_down — мощность вниз, Вт/м²
```

### 4.2. Расход теплоносителя

```
V_dot = Q_HK × 3.6 / (ρ × c_p × ΔT)  [л/ч]

где:
- Q_HK — мощность контура, Вт
- ρ — плотность теплоносителя, кг/м³ (≈1053 для 50% гликоля при 40°C)
- c_p — теплоёмкость, кДж/(кг·К) (≈3.21 для 50% гликоля при 40°C)
- ΔT — температурный перепад, К (T_supply - T_return)
```

### 4.3. Скорость потока

```
v = V_dot × 4 / (3600 × π × d_inner²) × 10⁶  [м/с]

где:
- V_dot — расход, л/ч
- d_inner — внутренний диаметр трубы, мм
```

### 4.4. Число Рейнольдса

```
Re = 1000 × v × d_inner / ν  [безразмерный]

где:
- v — скорость, м/с
- d_inner — внутренний диаметр, мм
- ν — кинематическая вязкость, мм²/с
```

### 4.5. Режим течения

```
- Ламинарный: Re < 2300
- Переходный: 2300 ≤ Re ≤ 4000
- Турбулентный: Re > 4000
```

### 4.6. Коэффициент трения λ

```
Ламинарный (Re < 2300):
  λ = 64 / Re

Переходный (2300 ≤ Re ≤ 4000):
  λ = λ_lam + (Re - 2300) / 1700 × (λ_turb - λ_lam)
  где λ_lam = 64 / 2300, λ_turb = ColebrookWhite(4000)

Турбулентный (Re > 4000):
  1 / √λ = -2 × lg(ε / (3.7 × d_inner) + 2.51 / (Re × √λ))
  где ε = 0.007 мм (шероховатость PE-Xa)
```

### 4.7. Удельные потери давления

```
R = 10000 × (v² × ρ × λ) / (2 × d_inner) × 100  [Па/м]

где:
- v — скорость, м/с
- ρ — плотность, г/см³ (≈1.053 для 50% гликоля)
- λ — коэффициент трения
- d_inner — внутренний диаметр, мм
```

### 4.8. Потери в вентиле

```
Δp_Vent = (V_dot / 1000 / Kv)² × 100000 × ρ  [Па]

где:
- V_dot — расход, л/ч
- Kv — коэффициент пропускной способности, м³/ч
  - HKV-D: Kv = 1.2
  - IV 1¼": Kv = 1.45
  - IV 1½": Kv = 1.5
- ρ — плотность, кг/м³
```

### 4.9. Суммарные потери

```
Δp_total = Δp_HK + Δp_Zul + Δp_Vent  [Па]

где:
- Δp_HK = L_hk × R — потери в контуре
- Δp_Zul = L_zul × R — потери в подводке
- Δp_Vent — потери в вентиле
```

### 4.10. Дросселирование для балансировки

```
zu_drosseln = Δp_max - Δp_total  [Па]

где:
- Δp_max — максимальные потери среди всех контуров коллектора
- Δp_total — потери текущего контура
```

### 4.11. Расчёт оборотов балансировочного клапана

**Типы клапанов:**
- **IV 1½"** — встроенный вентиль 1½ дюйма
- **IV 1¼"** — встроенный вентиль 1¼ дюйма
- **HKV-D** — балансировочный клапан РЕХАУ (кубическая характеристика)

**Формулы расчёта оборотов:**

```
IV 1½":   Обороты = 5.122 × Kv - 0.2106
IV 1¼":   Обороты = 5.1818 × Kv - 0.23
HKV-D:    Обороты = 4.2111 × Kv³ - 6.7436 × Kv² + 4.6613 × Kv - 0.712

где:
- Kv — коэффициент расхода, м³/ч
- Обороты — количество оборотов клапана (от положения "закрыто")
```

**Примечания:**
- Результат округляется до 0.1 оборота
- Для HKV-D рекомендуется Kv от 0.8 до 4.0
- При Kv < 0.5 результат может быть неточным

## 6. Требования к UI

### 6.1. Визуализация коллекторов

**Структура интерфейса:**
- Коллекторы отображаются как **отдельные карточки (блоки)**, расположенные вертикально
- Каждая карточка коллектора содержит:
  - Заголовок: "Коллектор 1", "Коллектор 2" и т.д.
  - Тип коллектора (выпадающий список: HKV-D, IV 1¼", IV 1½")
  - Таблицу контуров внутри карточки
  - Итоги коллектора

**Начальное состояние:**
- При открытии вкладки отображается **1 коллектор** с **4 контурами**
- Строки контуров пустые (пользователь вводит длины)
- Переключатель режима: "Рабочая температура" (по умолчанию)

**При добавлении нового коллектора:**
- Новый коллектор получает порядковый номер ("Коллектор 2")
- Внутри автоматически создаётся **1 контур** по умолчанию ("Контур 2.1")
- Структура сразу валидна для расчёта

### 6.2. Управление коллекторами

**Кнопки управления коллекторами:**
- Кнопка **"+ Добавить коллектор"** — отображается над или под списком коллекторов
  - Неактивна, если достигнут лимит 4 коллектора
  - Подсказка: "Максимум 4 коллектора"
- Кнопка **"Удалить коллектор"** (иконка корзины) — на каждой карточке коллектора
  - Неактивна, если остался 1 коллектор
  - Подтверждение удаления если коллектор содержит данные

**Удаление коллектора:**
- При удалении все контура удаляются вместе с коллектором
- Номера оставшихся коллекторов пересчитываются

### 6.3. Управление контурами

**Кнопки управления контурами (внутри карточки коллектора):**
- Кнопка **"+ Добавить контур"** — внутри каждого коллектора
  - Неактивна, если достигнут лимит 12 контуров
  - Подсказка: "Максимум 12 контуров на коллектор"
- Новый контур получает автоматически сгенерированное имя ("Контур 1.5")
- Значения длины по умолчанию — пустые или минимально допустимые

**Удаление контура:**
- Каждая строка контура содержит **иконку "Корзина"** (или "Удалить")
- При наведении на строку иконка становится видимой
- При удалении последнего контура в коллекторе — **коллектор удаляется автоматически**
- Пустые коллекторы не имеют смысла

### 6.4. Таблица контуров

**Визуальное различие полей:**
- **Поля ввода** (редактируемые): белый фон, редактируемый стиль
- **Поля результата** (автоматические): серый/бледный фон, только для чтения

**Столбцы таблицы:**
| Столбец | Параметр | Единица | Редактируемый | Стиль |
|---------|----------|---------|--------------|-------|
| № | Номер контура | — | Нет (авто) | Обычный |
| L_hk | Длина контура | м | Да | Поле ввода |
| L_zul | Длина подводки | м | Да | Поле ввода |
| L_total | Общая длина | м | Нет (авто) | Результат |
| S | Площадь | м² | Нет (авто) | Результат |
| Q_HK | Мощность | Вт | Нет (авто) | Результат |
| V_dot | Расход | л/ч | Нет (авто) | Результат |
| v | Скорость | м/с | Нет (авто) | Результат |

**Единицы измерения:**
- В заголовках столбцов указаны единицы измерения
- Пользователь не должен гадать: метры или сантиметры
- Все длины вводятся в метрах (м)
- Все давления отображаются в миллибарах (мбар)

**Inline editing:**
- Поля L_hk и L_zul редактируются непосредственно в строке таблицы
- При изменении значения автоматически пересчитываются результаты
- Валидация происходит при потере фокуса

### 6.5. Валидация и блокировка расчёта

**Блокировка расчёта:**
- Расчёт блокируется при наличии критических ошибок
- Кнопки "Рассчитать" неактивны, если есть ошибки валидации
- Список ошибок отображается под таблицей

**Типы ошибок:**
- Критические (блокируют расчёт):
  - Длина контура вне диапазона (10-500 м)
  - Длина подводки вне диапазона (1-100 м)
  - Отсутствуют данные для расчёта
- Предупреждения (не блокируют):
  - Переходный режим течения
  - Превышение давления (> 320 мбар)

**Логирование ошибок:**
- Все ошибки валидации записываются в лог
- Формат лога: `[Дата/Время] [Уровень] [Модуль] Сообщение`
- Лог доступен для просмотра в интерфейсе (меню "Справка" → "Лог")

### 6.6. Визуальные индикаторы

- **Референсный контур** — жирный шрифт, значок ★
- **Превышение давления** — красный цвет строки, иконка предупреждения
- **Переходный режим** — жёлтый цвет ячейки Re
- **Неактивный контур** — серый цвет (L_hk = 0)
- **Ошибка валидации** — красная рамка поля ввода, всплывающая подсказка
- **Пустое обязательное поле** — жёлтая рамка, подсказка при наведении

### 6.7. Переключатель режимов

**Переключатель "Температура расчёта":**
- "Рабочая температура" — результаты при T_mean = (T_supply + T_return) / 2
- "Расчётная температура" — результаты при t_cold (холодная пятидневка)

**Поведение:**
- По умолчанию: "Рабочая температура"
- При переключении таблица обновляется мгновенно (< 100 мс)
- Все результаты рассчитываются для обеих температур

### 6.8. Итоги коллектора

**Отображение под таблицей в карточке коллектора:**
- Количество контуров
- Общая длина труб (м)
- Суммарная мощность (Вт)
- Суммарный расход (л/ч, м³/ч)
- Потери при рабочей температуре (мбар)
- Потери при расчётной температуре (мбар)
- Тип клапана и рассчитанные обороты
- Предупреждение о превышении давления (> 320 мбар)

### 6.9. Общие итоги

**Панель общих итогов (под всеми коллекторами):**
- Общее количество коллекторов
- Общее количество контуров
- Общая мощность (Вт, кВт)
- Общий расход (л/ч, м³/ч)
- Статус валидации (зелёный/красный индикатор)

- Тесты для граничных условий (Re = 2300, Re = 4000)

- Тесты для балансировки контуров

- Интерфейс: RU (основной), EN, DE

## 10. Приложение: Пример расчёта

### 10.1. Исходные данные

```
L_hk = 100 м
L_zul = 20 м
VA_hk = 20 см
VA_zul = 5 см
q_zul = 10%
q_up = 256 Вт/м²
q_down = 5 Вт/м²
Труба RAUTHERM S 20×2.0 (d_inner = 16 мм)
Гликоль 50%, T_operating = 40°C, T_design = -30°C
```

### 10.2. Расчёт мощности

```
S_контур = L_hk / (100 / VA_hk) = 100 / 5 = 20 м²
S_подводка = L_zul / (100 / VA_zul) × (q_zul/100) = 20 / 20 × 0.1 = 0.1 м²
S_эфф = 20.1 м²
Q_HK = 20.1 × (256 + 5) = 5246 Вт
```

### 10.3. Расчёт при рабочей температуре (40°C)

```
Свойства гликоля 50% при 40°C:
  ρ = 1053 кг/м³ = 1.053 г/см³
  ν = 2.16 мм²/с
  c_p = 3.21 кДж/(кг·К)

Расход:
  V_dot = 5246 × 3.6 / (1053 × 3.21 × 10) = 0.56 м³/ч = 560 л/ч

Скорость:
  v = 560 × 4 / (3600 × π × 16²) × 10⁶ = 0.77 м/с

Число Рейнольдса:
  Re = 1000 × 0.77 × 16 / 2.16 = 5704 (турбулентный)

Коэффициент трения:
  λ ≈ 0.037 (по формуле Колбрука-Уайта)

Удельные потери:
  R = 10000 × (0.77² × 1.053 × 0.037) / (2 × 16) × 100 = 728 Па/м

Потери в трубе:
  Δp_Rohr = (100 + 20) × 728 = 87360 Па = 873.6 мбар

Потери в вентиле (HKV-D, Kv = 1.2):
  Δp_Vent = (560 / 1000 / 1.2)² × 100000 × 1053 = 22880 Па = 228.8 мбар

Суммарные потери:
  Δp_total = 873.6 + 228.8 = 1102.4 мбар > 320 мбар ❌
```

**Вывод:** При заданных параметрах потери превышают лимит 320 мбар. Требуется корректировка параметров.
