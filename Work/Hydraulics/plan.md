## 6. Критерии приёмки

### 6.1. Функциональные критерии
- [ ] Нумерация контуров корректна: 1, 2, 3, ..., 10, 11, 12
- [ ] После удаления контура номера перенумеровываются
- [ ] После удаления коллектора номера перенумеровываются
- [ ] Коллекторы отображаются в интерфейсе (вкладки TabControl)
- [ ] Можно переключаться между коллекторами
- [ ] Диалоговое окно подтверждения отображается при удалении контура
- [ ] Диалоговое окно подтверждения отображается при удалении коллектора
- [ ] При отмене удаления контур/коллектор не удаляется
- [ ] Кнопка удаления контура заблокирована, если в коллекторе только 1 контур
- [ ] Кнопка удаления коллектора заблокирована, если в системе только 1 коллектор

### 6.2. Нефункциональные критерии
- [ ] UI обновляется мгновенно (< 100 мс)
- [ ] Нет дублирования кода (CircuitViewModel удалён)
- [ ] Unit-тесты проходят
- [ ] Данные не сохраняются между сессиями

## 9. Примечания

### 9.1. Решения пользователя
1. **TabControl для переключения коллекторов** — наиболее интуитивный способ
2. **Без сохранения данных между сессиями** — данные существуют только в рамках одной сессии
3. **Предупреждение всегда при удалении** — защита от случайного удаления
4. **Удалить CircuitViewModel.cs** — класс не используется

### 9.2. Важные замечания
- Метод `RenumberCircuits()` уже существует (строки 358-364 в `CircuitsViewModel.cs`)
- Метод `RemoveCircuit()` уже вызывает `RenumberCircuits()` (строка 228)
- Проблема в том, что `CircuitNumber` не уведомляет UI об изменении
- Класс `CollectorData` уже использует `ObservableObject` и `ObservableProperty`
