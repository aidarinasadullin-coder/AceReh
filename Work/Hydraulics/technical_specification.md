# Техническое задание: Исправление нумерации контуров и коллекторов

## 1. Общее описание

### 1.1. Краткое описание задачи
Исправление критических багов в модуле гидравлического расчёта, связанных с нумерацией контуров и отображением коллекторов в интерфейсе.

### 1.2. Цель разработки
Обеспечить корректную нумерацию контуров (1, 2, 3... 10, 11, 12) и отображение списка коллекторов в интерфейсе пользователя.

### 1.3. Связь с существующей системой
Модуль гидравлического расчёта (`CircuitsViewModel`) использует модели `CircuitRow` и `CollectorData` для хранения данных. Проблемы затрагивают:
- Отображение номеров контуров в DataGrid
- Переключение между коллекторами
- Перенумерацию при удалении

## 2. Анализ проблем

### 2.1. Проблема №1: Нумерация контуров 1,1,1 вместо 10,11,12

#### 2.1.1. Симптом
При добавлении контуров после 9-го номера отображаются как 1,1,1 вместо 10,11,12.

#### 2.1.2. Корневая причина
**Файл**: `src/Models/Hydraulics/CircuitRow.cs`, строка 82

```csharp
/// <summary>
/// Номер контура
/// </summary>
public int CircuitNumber { get; set; }  // <-- ОБЫЧНОЕ свойство без уведомления!
```

Свойство `CircuitNumber` не является `ObservableProperty`, поэтому при изменении через метод `RenumberCircuits()` UI не получает уведомление об изменении.

#### 2.1.3. Механизм бага
1. Пользователь добавляет контуры 1-9 → номера корректны
2. Пользователь удаляет контур №5
3. Метод `RenumberCircuits()` перенумеровывает: 1,2,3,4,6,7,8,9 → 1,2,3,4,5,6,7,8
4. **НО**: `CircuitNumber` не уведомляет UI, поэтому DataGrid показывает старые номера
5. При добавлении новых контуров `circuitNumber = collector.Circuits.Count + 1` даёт 9, но отображается как 1 из-за кэшированного значения

**Примечание**: Метод `RemoveCircuit` уже вызывает `RenumberCircuits` (строка 228 файла `CircuitsViewModel.cs`), но проблема в том, что `CircuitNumber` не уведомляет UI об изменении.

#### 2.1.4. Сравнение с неиспользуемым классом
**Файл**: `src/ViewModels/Hydraulics/CircuitViewModel.cs`, строки 19-20

```csharp
[ObservableProperty]
private int _circuitNumber;  // <-- ПРАВИЛЬНО! Уведомляет UI
```

Класс `CircuitViewModel` имеет корректную реализацию, но **не используется** в приложении!

### 2.2. Проблема №2: Коллекторы не отображаются в интерфейсе

#### 2.2.1. Симптом
Кнопка "Добавить коллектор" нажимается, но новые коллекторы не появляются в интерфейсе.

#### 2.2.2. Корневая причина
**Файл**: `src/Views/Hydraulics/CircuitsView.xaml`

В XAML **НЕТ** элемента для отображения списка коллекторов и переключения между ними:
- Нет TabControl
- Нет ListBox
- Нет ComboBox для выбора коллектора

Есть только:
- Строка 295: отображение номера **выбранного** коллектора
- Строка 312: привязка к контурам **выбранного** коллектора

#### 2.2.3. Механизм бага
1. Пользователь нажимает "Добавить коллектор"
2. Метод `AddCollector()` создаёт коллектор и добавляет в `Collectors`
3. `SelectedCollectorIndex` устанавливается на новый коллектор
4. **НО**: В интерфейсе нет элемента для отображения списка коллекторов!
5. Пользователь видит только контуры текущего коллектора, но не может переключаться

#### 2.2.4. Примечание: CollectorData уже правильно реализован
**Файл**: `src/ViewModels/Hydraulics/CircuitsViewModel.cs`, строки 15-57

Класс `CollectorData` определён внутри `CircuitsViewModel.cs` и уже использует `ObservableObject`:
```csharp
public partial class CollectorData : ObservableObject
{
    [ObservableProperty]
    private int _collectorNumber;  // <-- УЖЕ уведомляет UI!
    // ...
}
```

**Важно**: Свойство `CollectorNumber` уже уведомляет UI через INotifyPropertyChanged. Проблема только в отсутствии UI-элемента для отображения списка коллекторов.

### 2.3. Проблема №3: Отсутствует перенумерация коллекторов при удалении

#### 2.3.1. Симптом
При удалении коллектора №2 из трёх, остаются коллекторы №1 и №3 вместо №1 и №2.

#### 2.3.2. Корневая причина
**Файл**: `src/ViewModels/Hydraulics/CircuitsViewModel.cs`, строки 186-198

```csharp
[RelayCommand]
private void RemoveCollector(CollectorData collector)
{
    if (collector != null && Collectors.Contains(collector))
    {
        Collectors.Remove(collector);
        // НЕТ перенумерации!
        if (SelectedCollectorIndex >= Collectors.Count)
        {
            SelectedCollectorIndex = Math.Max(0, Collectors.Count - 1);
        }
        ...
    }
}
```

Метод `RenumberCircuits()` есть для контуров (строки 358-364), но **НЕТ** метода `RenumberCollectors()` для коллекторов.

#### 2.3.3. Примечание: RenumberCircuits уже существует
**Файл**: `src/ViewModels/Hydraulics/CircuitsViewModel.cs`, строки 358-364

Метод `RenumberCircuits` уже существует и корректно реализован:
```csharp
private void RenumberCircuits(CollectorData collector)
{
    for (int i = 0; i < collector.Circuits.Count; i++)
    {
        collector.Circuits[i].CircuitNumber = i + 1;
    }
}
```

**Проблема**: Метод `RemoveCircuit` уже вызывает `RenumberCircuits` (строка 228), но `CircuitNumber` не уведомляет UI об изменении. Нужно только добавить `RenumberCollectors()` для коллекторов.

private void RemoveCollector(CollectorData collector)

}

### 4.5. Диалоговое окно подтверждения удаления

**Требование**: При удалении контура или коллектора отображать диалоговое окно с подтверждением.

**Текст диалога для удаления контура**:
```
Заголовок: "Удаление контура"
Сообщение: "Вы уверены, что хотите удалить контур №{N}?"
Кнопки: "Удалить" / "Отмена"
```

**Текст диалога для удаления коллектора**:
```
Заголовок: "Удаление коллектора"
Сообщение: "Вы уверены, что хотите удалить коллектор №{N}? Все контуры этого коллектора будут удалены."
Кнопки: "Удалить" / "Отмена"
```

**Реализация**:
- Использовать `MessageBox.Show()` из пространства имён `System.Windows`
- Возвращать `true` при нажатии "Удалить", `false` при нажатии "Отмена"
- Если пользователь отменил — не выполнять удаление

**Пример кода**:
```csharp
private bool ConfirmDeleteCircuit(int circuitNumber)
{
    var result = MessageBox.Show(
        $"Вы уверены, что хотите удалить контур №{circuitNumber}?",
        "Удаление контура",
        MessageBoxButton.YesNo,
        MessageBoxImage.Warning
    );
    return result == MessageBoxResult.Yes;
}

private bool ConfirmDeleteCollector(int collectorNumber)
{
    var result = MessageBox.Show(
        $"Вы уверены, что хотите удалить коллектор №{collectorNumber}?\nВсе контуры этого коллектора будут удалены.",
        "Удаление коллектора",
        MessageBoxButton.YesNo,
        MessageBoxImage.Warning
    );
    return result == MessageBoxResult.Yes;
}
```

#### 4.5.2. Методы блокировки кнопок удаления

**CanRemoveCircuit** — блокировка кнопки удаления контура:
```csharp
private bool CanRemoveCircuit(CircuitRow circuit)
{
    // Нельзя удалить, если:
    // 1. Контур не выбран (circuit == null)
    // 2. В коллекторе только 1 контур (минимум 1 контур должен остаться)
    if (circuit == null)
        return false;
    
    var collector = Collectors[SelectedCollectorIndex];
    return collector.Circuits.Count > 1;
}
```

**CanRemoveCollector** — блокировка кнопки удаления коллектора:
```csharp
private bool CanRemoveCollector(CollectorData collector)
{
    // Нельзя удалить, если:
    // 1. Коллектор не выбран (collector == null)
    // 2. В системе только 1 коллектор (минимум 1 коллектор должен остаться)
    if (collector == null)
        return false;
    
    return Collectors.Count > 1;
}
```

**Важно**: Методы `CanRemoveCircuit` и `CanRemoveCollector` должны вызываться через `CanExecute` атрибут `[RelayCommand]` для автоматической блокировки кнопок в UI.

## 7. Решённые вопросы

### 7.1. UI для переключения коллекторов
**Решение**: TabControl — вкладки для каждого коллектора.

**Обоснование**: Наиболее интуитивный и стандартный способ переключения между коллекторами в WPF-приложениях.

### 7.2. Сохранение данных
**Решение**: Без сохранения — данные теряются при закрытии приложения.

**Обоснование**: В текущей версии реализация сохранения не требуется. Данные существуют только в рамках одной сессии работы.

### 7.3. Валидация при удалении
**Решение**: Предупреждение всегда — диалоговое окно с подтверждением.

**Обоснование**: Защита пользователя от случайного удаления данных. Диалоговое окно должно отображаться при любой попытке удаления контура или коллектора.

### 7.4. Удаление CircuitViewModel.cs
**Решение**: Удалить файл `src/ViewModels/Hydraulics/CircuitViewModel.cs`.

**Обоснование**: Класс не используется в приложении, является дублированием функциональности `CircuitRow`.
