# Changelog

## [1.6.0] - 2026-09-15

### Добавлено
- **Подсказки-советы при нарушении тепловых лимитов** (план docs/plans/2026-09-13-thermal-advice-plan.md, ревью R-2026-09-14-01/R-2026-09-15-01): если обратка ниже 0 °C или перепад ΔT выше 30 K, под полями «Температура подачи» и «Шаг укладки» появляются тёплые подсказки с лечением; ориентир един — «для ΔT ≈ 15 К» (T_средняя + 7,5 °C), одна итерация снимает оба нарушения. Чип «Температура обратки» подсвечивается тёплой охрой при отрицательном значении; «Поток вниз q↓» показан охрой постоянно — семантика «потери» (новый токен `Status.Warning.Dark` #8A6100). Постоянная подсказка «Рекомендуется: …» скрывается при активных советах и возвращается после их устранения (решение №8, вариант A). Советы ничего не блокируют — ошибки валидации по-прежнему в статус-баре. State ownership без изменений

## [1.5.0] - 2026-09-13

### Добавлено
- **Экспорт спецификации закупки в Excel** — в меню кнопки «Отчёт PDF ▾» на шаге «Результаты» новый пункт «Спецификация XLSX»: книга .xlsx с листом «Спецификация» (труба, резьбозажимные соединения — 2 шт на каждый контур, коллекторы HKV с артикулами, итого по проекту) и листом «Контуры» (наладка: длины, площадь, мощность, расход, Δp, обороты клапана, преднастройка). Числа пишутся числовыми ячейками — суммируются в Excel, разделитель рисуется по локали пользователя
- **Артикулы приведены к канону rehau_products.json**: трубы 17×2,0 → 1200170000, 20×2,0 → 1200200000, 25×2,3 → 1200250000 (были 12180501001/…2001/…3001); в каталог добавлены резьбозажимные соединения — 17×2 → 12506073002, 20×2 → 12506173002; РЗС 25×2,3 — артикул уточняется (позиция выводится с пустым артикулом и примечанием)

### Технически
- **Установщик: починен даунгрейд-гард** — ключ деинсталляции строится из `#define MyAppId` (одинарные скобки; прежде `SetupSetting("AppId")` возвращал `{{…}` с двойной скобкой, ключ никогда не находился и предупреждение при установке старой версии поверх новой не показывалось никогда), сравнение версий упаковано в Int64 (`PackVersionStr` → `PackVersionComponents` + `ComparePackedVersion` — функция принимает только Int64, на строках версий падает Type Mismatch), в тихом режиме (/SILENT, /VERYSILENT) даунгрейд прерывается без вопроса. Сетап пересобран, smoke даунгрейда пройден (3 сценария с /LOG) (ревью R-2026-09-13-05)
- INSTALL.md: структура установленной папки приведена к фактической поставке (`docs\manual\README.html`; папок `docs\Инструкция полная\`, `media\`, `LatoFont\` в поставке нет), размеры уточнены по факту (сетап ~68 MB, развёрнутая ~226 MB, на диске ~300 MB)
- ClosedXML 0.105.1 (MIT); новый `ResultsSpecificationDataBuilder` собирает данные из канонических снимков ProjectSession без зависимости от ViewModels; сервис `ExcelExportService` повторяет паттерн `PdfExportService` (путь снаружи, bool наружу)
- `CollectorRepository`: починен биндинг json-ключей snake_case (`collectors_hkv`, `article_number`) — ранее корневые ключи не совпадали с именами свойств и данные молча подменялись встроенными дефолтами
- План docs/plans/2026-09-13-excel-specification-plan.md, ревью R-2026-09-13-02

## [1.4.0] - 2026-09-13

### Добавлено
- **Ручной ввод температуры поверхности (+1…+7 °C)** — поле «Температура поверхности» в тепловом модуле редактируемое: целые значения +1…+7 задаются вручную, +3/+5/+7 по-прежнему выбираются пресетами «Антиобледенение», «Таяние», «Интенсивное» (ввод 3/5/7 автоматически выбирает пресет). В списке режимов 7 пунктов; подпись у поля показывает происхождение значения — «из режима „Таяние“» или «своё значение»
- **Предупреждение «t_пов ≤ t_нар»** — необлокирующая подсказка под полем: температура поверхности не выше температуры наружного воздуха — расчётная мощность будет отрицательной
- **Человекочитаемые подписи режима** — Results и PDF «Результаты расчёта» печатают «Таяние (+5 °C)» / «Пользовательский (+4 °C)» вместо сырых имён enum («Melting», «Manual4»)

### Технически
- Каноническое состояние и все механики без изменений: владелец t_пов — поле `Mode` теплового среза, один канал мутации (`ForMode`); `.smc`-wire совместим (ручные значения пишутся именами `manual1…manual6`, старые файлы читаются как есть); физика расчёта, формула t_P в записке, Undo/Redo не менялись

## [1.3.0] - 2026-09-12

### Изменено
- **Источник скорости ветра v_H** — переход с «средняя скорость ветра за отопительный период» (`wind_avg_t_le_8`) на «максимальная из средних скоростей по румбам за январь» (`wind_max_jan`): консервативная оценка, α и расчётная мощность возрастают (Майкоп: 3,1 → 5,4 м/с). У трёх городов без данных (Мариуполь, Запорожье, Аскания-Нова) подставляется 0 — поле подсвечивается валидацией
- **Чекбокс «Повышенные требования»** — ступень вниз от автоматики города: −10 → −15, −15 → −20 (ранее всегда −20); при автоматике −20 и без выбранного города неактивен; снимается возвратом к автоматике и сбрасывается при смене города или «Сбросить к данным города»

### Удалено
- **Выпадающий список «Климатическая зона»** — контрол не публиковал выбор в каноническое состояние (молча затирался зеркалом снимка); зона теперь производная итоговой расчётной температуры: −10 → M10, −15 → M15, ≤ −20 → M20. M20_Plus не порождается и остаётся legacy для чтения старых .smc

### Исправлено
- **Зона в PDF** — печатается человекочитаемо («M15 · колонка −15 °C») вместо сырого имени enum (оба PDF-экспорта: «Результаты расчёта» и расчётная записка)
- **Граница t₅ = −37 °C** — расчётная температура (−20 °C) больше не расходится с зоной (M20); прежде температура относила границу к −15

## [1.0.0] - 2026-04-06

### Добавлено
- **Климатический модуль** — данные по 550 городам РФ (СП 131.13330.2025)
- **Модуль конструкции** — расчёт многослойной конструкции ("пирог")
