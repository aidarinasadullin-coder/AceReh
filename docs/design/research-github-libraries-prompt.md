Роль: исследователь open-source библиотек для WPF-приложения. Строгие
ограничения: лицензия MIT (или эквивалентно permisсивная), .NET 8 / WPF
(net8.0-windows), минимальный след зависимости — мы строим собственный
токен-компонентный каркас, UI-фреймворки (Wpf.Ui, MahApps, ModernWpf,
HandyControl, MaterialDesign) НЕ рассматриваются.

Контекст репозитория: D:\IA\ace — «Калькулятор снеготаяния REHAU»,
CommunityToolkit.Mvvm 8.2.2, QuestPDF, SharpVectors, своя дизайн-система
токенов (docs/design/brandbook-2026-application.md), план редизайна
(docs/design/redesign-plan.md). Прочитай их для контекста.

Кандидаты для проверки (по одному разделу на каждого):

1. **VirtualizingWrapPanel** (GitHub: s-baer/VirtualizingWrapPanel) —
   адаптивная сетка карточек с виртуализацией для KPI-чипов и будущих
   карточных гридов. Проверить: лицензия, последний релиз и активность,
   поддержка .NET 8, NuGet-пакет/версия, поведение при изменении ширины
   окна (breakpoints?), виртуализация с переменной высотой, риски.
2. **MicaWPF** (GitHub: SIMULATAN/MicaWPF) — системный бэкдроп Mica/Acrylic
   для окна без всего фреймворка. Проверить: лицензия, поведение на
   Windows 10 (fallback?), совместимость с самописным WindowChrome
   (src/MainWindow.xaml использует System.Windows.Shell.WindowChrome),
   влияние на производительность/перезагрисовку, .NET 8.
3. **XamlFlair** (GitHub: XamlFlair/XamlFlair) — декларативные анимации
   переходов. Проверить: лицензия, .NET 8, актуальность (репозиторий
   может быть заморожен — приемлемо ли), интеграция с ContentControl-
   навигацией, альтернатива «свои Storyboard» — сравни трудозатраты.
4. **Fluent UI System Icons** (GitHub: microsoft/fluentui-system-icons) —
   источник иконок вместо инлайн-Path-геометрий. Проверить: лицензия,
   способ интеграции в WPF (готового официального WPF-пакета нет?),
   варианты: выгрузка нужных SVG → XAML-геометрии скриптом, сторонние
   обёртки (оценить их лицензии и живость), размер итогового словаря.
   Рекомендация: какой механизм взять (генерация Icon.* словаря из SVG).

Метод: лицензию и метаданные — по GitHub + nuget.org (WebSearch/WebFetch);
совместимость — по readme/cspric репозиториев; активность — дата последнего
релиза/коммитов, число открытых критических issues. Репозиторий D:\IA\ace
читать можно; ИЗМЕНЯТЬ ФАЙЛЫ ЗАПРЕЩЕНО — это исследование.

Результат (финальное сообщение):
1. Сравнительная таблица: кандидат | лицензия | NuGet/версия | активность |
   .NET 8 | интеграция | риски | вердикт (adopt / defer / reject).
2. По каждому adopt — минимальные шаги интеграции (пакет, строки кода,
   затрагиваемые места).
3. PoC-план на ~0,5 дня: что именно собрать руками, чтобы принять финальное
   решение (критерии успеха/отказа по каждому).
4. Если кандидат проваливает лицензию/активность — предложить живую
   альтернативу с тем же назначением.

## Дополнительные темы (второй заход, 2026-09-04)

5. **QuestPDF — лицензионный комплаенс (критично, не UI).** В проекте
   используется QuestPDF 2024.12.3 (`src/SnowMeltingCalculator.csproj`),
   генерация PDF-отчётов. Проверить по первоисточникам (questpdf.com,
   GitHub): условия Community-лицензии — порог годовой валовой выручки
   компании (~$1M), применимость к приложению, распространяемому от имени
   REHAU (крупная компания). Если Community-условия не выполняются:
   варианты — покупка Professional (только зафиксировать порядок цен) или
   миграция на PDFsharp/MigraDoc (MIT) — оценить объём работ по текущим
   билдерам (`src/Services/Results/ResultsPdfDataBuilder.cs`).
   Вердикт: остаёмся / миграционный план.
6. **UI-автотесты для фаз редизайна.** Кандидаты: FlaUI (проверить
   лицензию — Apache-2.0), WinAppDriver (статус поддержки Microsoft),
   альтернативы. Вопрос к владельцу заранее: допускаем ли Apache-2.0 как
   исключение из MIT-фильтра для dev-only зависимости (в дистрибутив
   приложения не попадает)? Оценить: минимальный smoke-тест каркаса окна
   (навигация по 5 модулям, AutomationProperties уже проставлены),
   вписывание в `dotnet test`.
   Вердикт: adopt/defer/reject.

Правила те же: лицензии — по первоисточникам, репозиторий read-only,
результат — таблица + вердикты + шаги.
