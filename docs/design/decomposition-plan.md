# План серии DE: decomposition hotspot-доменов после редизайна

> Статус: **v1 (2026-09-06). Согласован владельцем.** Собственная серия
> (нумерация DE, вне нумерации редизайна). Старт серии — **после приёмки
> финальной фазы редизайна**: до тех пор churn-данные искажены работой
> по вьюхам, и ревью зафиксировало бы движущуюся цель.
> Опирается на: исследование больших файлов и hotspot-анализ (2026-09-06,
> журнал п.1), форматы линий «состояние → отображение» из
> `docs/architecture/` (ADR-журнал), спецификацию отчёта `docs/report-spec.md`.
>
> Правила ведения работ (наследуются):
> - **запуск каждой фазы — только по явной команде владельца**;
> - каждая фаза передаётся как **незакоммиченный, собираемый** набор с
>   зелёным `dotnet test`; владелец ревьюит и коммитит;
> - **state ownership не меняется** — каждая фаза завершает handover
>   записью «state ownership без изменений»; появление нового writer —
>   только через ADR (в серии не ожидается: презентеры — читатели state);
> - DE-2 (review) — read-only; реализация любых швов — отдельными фазами
>   после утверждения владельцем вердикт-таблицы;
> - инварианты R1–R6 проверяются `ArchitectureRulesTests` в каждом handover;
> - `.smc`-контракт и round-trip не затрагиваются.

## 0. Стратегия

Три ступени: **DE-1 пересчёт hotspots → DE-2 review (read-only) →
DE-3…DE-7 мини-фазы** по утверждённым вердиктам. Вердикт-логика: дробить
только при **≥2 независимых ответственностях + высокий churn +**
(страдают тесты или ревью). Размер без churn и без нарушения SRP — не
дефект. Одна фаза = один домен; презентер и XAML не смешиваются.
Размеры: S ≈ вечер, M ≈ 2–3 вечера, L ≈ спринт.

Предварительный замер (2026-09-06, **до** завершения редизайна;

## DE-2 — Decomposition review (M, read-only) — выполнена 2026-09-06, вердикт-таблица утверждена владельцем (2026-09-07, журнал п.3)

По каждому домену — пять вопросов: (1) какие ответственности реально в
файле; (2) какие швы естественны; (3) что мешает тестированию; (4) риск
для R1–R6; (5) дробить ли (вердикт-логика §0).

Проверяемые гипотезы швов (уточняются по содержимому):

- **Results**: Calculation Methods (~400 строк) — кандидат на вынос в
  **презентер «canonical state → строки отчёта»** (чистая функция, без
  WPF-типов). Компонент переиспользуется генератором пояснительной
  записки (§6). Observable Properties (438 строк проекций) — вердикт
  может быть «не трогать»: проекции — суть VM-адаптера. Команды (~460) —
  низкий приоритет.
- **Circuits**: Computed Properties (~250) + Private Methods (~450) —
  тот же паттерн презентера строк таблицы контуров; одна методика на
  оба домена.
- **CircuitsView.xaml** (1176): швы по факту (user-controls по секциям);
  отдельный вердикт по дублям стилей → тема.
- **ResultsViewModelOpenProjectTests** (3230): механическое дробление по
  сценариям, без изменения тестов.
- **DI** (799+819): per-slice extension-группировки; `DiRegistrationTests`
  проходит без правок.

Выход: **вердикт-таблица** (файл → решение → шов → объём → риски).
Реализация — только после утверждения владельцем.

Приёмка: таблица утверждена владельцем; ничего не реализовано.
**Итог (журнал п.3): серия сужена до DE-3 + DE-5; DE-4 и DE-6 закрыты
без работы.**

## 6. Связка с генератором пояснительной записки

Сценарий **(а), согласованный**: генератор — отдельный чистый сервис,
вход — canonical state (`ProjectSession` + slices), выход — документ;
без зависимостей от VM/UI. Тогда генератор **не зависит от серии DE** и
может планироваться параллельно; DE-3 дополнительно даёт ему готовый
презентер строк. UI-интеграция генератора в Results — только после DE-3.
Ограничения генератора: docx/OpenXML или шаблон, без Interop; `.smc`
не трогать; тесты генератора отдельно от тестов VM; отталкиваться от
`docs/report-spec.md`.

## 7. Hygiene-трек (вне серии, параллельно)

- выполнено (2026-09-06): `docs/workspace/` выведен из git, правило в
  `.gitignore`, урок в `docs/agents/lessons.md`;

  `docs/инструкция/` из git; history rewrite существующего пака
  (дорого, ломает хеши — отдельная фаза с гейтом).

## 8. Критерии завершения серии

Вердикт-таблица DE-2 утверждена; все утверждённые ею фазы приняты;
контрольный hotspot-замер показывает остывание обработанных доменов;
архитектурные инварианты зелёные; state ownership — без изменений по
всем handover.
