# Идеи (копилка)

Копилка идей для будущих фаз. Пополнение — по итогам исследований аналогов и
обсуждений с владельцем. Реализация каждой — только по явному решению владельца.

---

## 1. Сравнение вариантов конструкции (до 5 вариантов)

- **Источник:** eltherm Designer (параллельное сравнение до 5 вариантов дизайна),
  CompuTrace (сравнение давлений/изоляции). Исследование аналогов 2026-09-08.
- **Суть:** параллельный расчёт нескольких вариантов конструкции пола
  (толщины слоёв, материалы, УГВ) с выводом таблицы сравнения:
  мощность, сопротивление R, толщина, стоимость трубы.
- **Где применимо:** шаги «Конструкция» и «Тепловой расчёт».

## 2. Подсказки «мощности не хватает» с предложением решения

- **Источник:** LoopCAD — supplemental heat: при превышении лимитов программа
  сама предлагает дополнительное отопление. Исследование аналогов 2026-09-08.
- **Суть:** если расчёт показывает превышение лимитов (температура поверхности,
  шаг укладки, удельная мощность) — вместо простой ошибки валидации показывать
  подсказку с вариантами: уменьшить шаг, выбрать трубу большего диаметра,
  заложить дополнительное отопление.
- **Где применимо:** «Тепловой расчёт», «Результаты».
- **Статус:** реализовано и **принято владельцем 2026-09-15** (версия 1.6.0):
  подсказки-советы под полями подачи/шага с единой целью «для ΔT ≈ 15 К»,
  тёплый акцент обратки при < 0 и потока вниз q↓ (план
  [2026-09-13-thermal-advice-plan.md](plans/2026-09-13-thermal-advice-plan.md),
  ревью R-2026-09-13-06/-07, R-2026-09-14-01, R-2026-09-15-01). Кандидаты v2:
  гидравлические советы, кнопка «Применить ориентир».

## 3. Экспорт спецификации в Excel с артикулами

- **Источник:** обсуждение презентации для руководства с владельцем
  (2026-09-13).
- **Суть:** в «Результатах» — выгрузка .xlsx со спецификацией закупки:
  типоразмеры, количество, метраж и **артикулы**. Артикулы уже есть в
  данных (`rehau_products.json`, модели `Collector`/`PipeType`), но сейчас
  не выводятся ни в PDF-отчёт, ни куда-либо ещё. Решить заодно, показывать
  ли артикулы в PDF. Листы: «Спецификация», «Контуры» (наладка).
- **Где применимо:** шаг «Результаты».
- **Статус:** одобрено владельцем 2026-09-13; план
  (`docs/plans/2026-09-13-excel-specification-plan.md`, ревью
  R-2026-09-13-02), реализовано и **принято владельцем 2026-09-13**
  (версия 1.5.0).

## 5. «Проверить обновления» в меню «Файл»

- **Источник:** обсуждение с владельцем 2026-09-20. Реакция владельца:
  одобрено.
- **Суть:** «Файл → Проверить обновления»: запрос к каналу раздачи
  (Google Drive) о последней версии, сравнение с версией сборки, при
  расхождении — сообщение со ссылкой/открытием папки выдачи. Закрывает
  вопрос «разослан ли старый сетап» (правило №20): программа сама знает,
  что вышла новая версия. Механизм сверки (публичный манифест версии vs
  rclone-перечень папки) — решить на этапе плана.
- **Где применимо:** меню «Файл».
- **Кандидат-пара:** диалог «Что нового» при первом запуске обновлённой
  версии (выжимка из CHANGELOG).

## 7. Гидравлические советы (советы-подсказки с лечением)

- **Источник:** обсуждение с владельцем 2026-09-20; кандидаты v2
  фиксировались ещё после идеи №2 (1.6.0). Реакция владельца:
  **принято** — при условии «сделать без грязи».
- **Суть:** паттерн ThermalAdviceService (1.6.0) переносится на
  гидравлический срез: при нарушении лимитов РЕХАУ под полем появляется
  подсказка с лечением, а не только ошибка в статус-баре. Лимиты:
  потери ≤ 320 мбар, скорость 0.5–2.0 м/с, длина ≤ 120 м
  (`HydraulicsConstants.cs`). Симптом → лечение: потери > 320 мбар →
  «разбить контур / диаметр больше»; скорость < 0.5 м/с → «труба 17×2,0
  или меньше шаг — вырастет расход»; скорость > 2.0 м/с → «диаметр
  больше или разбить контур»; длина > 120 м → «разбить на два контура».
  Кнопка «Применить» — только для советов, лечащихся одним действием
  (например, смена типоразмера трубы).
- **«Без грязи» (условие владельца):** правила советов — в сервисе на
  гидравлическом срезе (аналог `ThermalAdviceService`), без записей
  VM→VM и без новых писателей в канон (R1–R6 не затрагиваются);
  состояние owner-проверки «state ownership без изменений» — в плане.
- **Где применимо:** шаг «Гидравлика» (контур/коллектор).

## 8. Автосохранение и восстановление сессии

- **Источник:** обсуждение с владельцем 2026-09-20. Реакция владельца:
  одобрено; хранение — рядом с настройками приложения (инфраструктура
  AppSettings).
- **Суть:** периодический снапшот незавершённого проекта (раз в ~2 мин
  при изменениях) в служебную папку рядом с AppSettings (AppData);
  при старте после краха/некорректного закрытия — предложение
  «Восстановить проект?». Снапшот пишется в формате .smc (тот же wire,
  отдельный канал) — `.smc`-совместимость не меняется; каноническое
  состояние не расширяется. Ретеншн: один снапшот + временная метка.
- **Где применимо:** всё приложение (фоновый механизм + диалог при
  старте).

## 9. Диалог «Что нового» после обновления

- **Источник:** обсуждение с владельцем 2026-09-20. Реакция владельца:
  одобрено. Кандидат-пара к идее №5.
- **Суть:** при первом запуске обновлённой версии — диалог с выжимкой

- **Где применимо:** старт приложения.

## 10. Копирование таблиц «Результатов» в буфер обмена

- **Источник:** обсуждение с владельцем 2026-09-20. Реакция владельца:
  интересно, **отложено** («оставим а потом»); реализуемость оценить
  заранее.
- **Оценка реализуемости (2026-09-20):** таблицы «Результатов» —
  `ItemsControl` с шаблонами, встроенного копирования WPF `DataGrid`
  нет. Но строки уже собираются из канонических снимков
  (`ResultsSpecificationDataBuilder` — тот же источник, что лист XLSX),
  поэтому кнопка «Копировать» на таблице = сборка TSV → `Clipboard` —
  дёшево (один мини-план). Полноценный HTML-формат буфера (таблица с
  форматированием при вставке в Word/почту) — дороже, опционально.
- **Где применимо:** шаг «Результаты» (таблицы контуров/коллекторов).
