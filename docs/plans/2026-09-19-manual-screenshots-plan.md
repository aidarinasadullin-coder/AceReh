## 0. Суть

Иллюстрации в `README.html` (собирается из `docs/manual/src/template.html` +
`docs/manual/src/media/*.png` скриптом `docs/manual/build_manual.py`) двух
семейств сделаны ручными кропами вне репо — без правила кадра и без
воспроизводимости. Проверено извлечением всех 29 инлайнов из собранного
`README.html` и просмотром.

Полноразмерные скрины шагов (1440×900: `00-trim`, `01-construction`,
`03-hydraulics`, `03b`, `04-results`, pg/pz) — в порядке, их не трогаем.

Дополнительно вскрыт инфраструктурный риск: после LFS-миграции волны 1
(коммит `443506c`) все 33 media-файла — Git LFS; в текущей рабочей копии они
лежат указателями (~130 байт, `version https://git-lfs...`). Собранный ранее
`README.html` это скрывает (он содержит настоящие PNG), но **пересборка
сейчас молча заинлайнит base64 указателей** — инструкция станет битой.

## 1. Подход

Корневая причина — кропы делались вручную вне репо. Лечим не «перекадрировать
ещё раз», а правилом кадра + детерминированным инструментом:

1. **Правило кадра** (все новые кропы):
   - резать по границам блоков UI (карточка/панель целиком), никогда
     посередине текста, поля или строки шага;
   - степпер — все 5 шагов целиком с паддингом ≥12px;
   - строка состояния — только сама полоса (без панели выше), обрезка по
     правому краю содержимого + паддинг ≥16px, единая высота семейства;
   - внутри семейства — одинаковая ширина (степперы ~320–360px, статусбары
     под ширину карточки `.sb-card`, ~520–560px).
2. **Инструмент**: `python tools/manual-crops.py` — новый скрипт: читает
   эталонные полные скрины из `docs/manual/src/shots/` (новая папка, LFS),
   вырезает кропы по зашитым координатам, пишет в `src/media/`. Координаты
   верифицируются один раз — дальше воспроизводимо.
3. **Пересъёмка состояний**: 4 состояния приложения дают все недостающие
   кадры (чек-лист в §4).

## 2. Волны

### Волна 0 — рабочая копия (без правок кода)

| Шаг | Действие |
|---|---|
| 0.1 | `git lfs pull` — смudge всех 33 media-файлов; проверка: каждый файл начинается с `\x89PNG` и открывается с реальными размерами |
| 0.2 | Зафиксировать в handover-заметке: после любого `git clone`/`checkout` без LFS media — указатели, пересборка инструкции до `git lfs pull` запрещена (после волны 1 скрипт сам это ловит) |

### Волна 1 — гейт в сборке (единственная правка кода)

| Файл | Правка |
|---|---|
| `docs/manual/build_manual.py` | В `inline()`: перед инлайном проверять сигнатуру `\x89PNG\r\n\x1a\n`; иначе `sys.exit` с именем файла и подсказкой «файл — LFS-указатель или не PNG: выполните git lfs pull». Дополнительно проверить плейсхолдеры, для которых файл отсутствует на диске, но есть в LFS-треке, — сообщение то же |

Риск закрыт: сборка бьёт громко и объясняет причину, вместо тихой битой
инструкции. `ManualVersionGateTests` не затрагивается.

### Волна 2 — инструмент кропов + правка шаблона

| Файл | Правка |
|---|---|
| `tools/manual-crops.py` (новый) | Кропы из `src/shots/*.png` по координатной таблице (источник → прямоугольники → выход в `src/media/`), паддинги по правилу кадра §1 |
| `docs/manual/src/shots/` (новая) | Эталонные полные скрины 1440×900 состояний из чек-листа §4 (LFS подхватит по `*.png`) |
| `docs/manual/src/template.html` | Строки 250–267 (сценарии) и 243–248 (sb-grid): переименование `extracted-01.png` → `sb-recalc-scenario.png`, `extracted-02.png` → `sb-error-range.png` (дубликат `sb-error.png` устраняется), актуальные alt-тексты; выравнивание двух колонок сценариев (`.two-col`) по верхней кромке кадров; cap-подписи — без изменений по тексту |

### Волна 3 — пересъёмка состояний (запуск приложения, чек-лист)

Каждое состояние → полный скрин окна 1440×900 (масштаб 100%) в `src/shots/`
с именем `state-<имя>.png`:

| Состояние | Как воспроизвести | Даёт кадры |
|---|---|---|
| `state-ready` | Открыть проект, рассчитать, шаг «Результаты» (статус «РЕЗУЛЬТАТЫ — Все данные готовы») | `sb-ready` |
| `state-recalc` | На «Климате» поменять температуру −15 → −18, НЕ нажимать «Рассчитать»: шаги 3 и 5 гаснут, «Гидравлика» бирюзовая, статус «Климатические данные изменены. Требуется пересчёт» | `c-stepper` (степпер целиком), `sb-recalc-scenario` |
| `state-error` | В «Климате» ввести −50,0: шаг «Климат» с ⚠, поле с красной обводкой, статус «Температура должна быть от −50 до +10» | `c-error-stepper`, `sb-error-range` |
| `state-info` | На «Конструкции» задать УГВ < 1 м (статус «КОНСТРУКЦИЯ — Уровень грунтовых вод…») | `sb-info2` |

Статус `sb-recalc` («ТЕПЛОВОЙ — Шаг укладки изменён…») можно кропнуть из
существующего полного скрина тёплового шага (`state-thermal-extra`, снимается
заодно) — либо оставить текущий кроп, обрезав у него верхний мусор, если
владелец предпочитает минимальную пересъёмку (открытый вопрос V2).

## 3. Что не входит в скоуп

- Код приложения (WPF): не трогаем вообще.
- Полноразмерные скрины шагов (00-trim, 01-, 03-, 03b-, 04-results) и
  PDF-страницы (pg/pz) — остаются как есть.
- Лайтбокс/лупа в шаблоне (решение владельца `60e76cd`) — не трогаем.
- Сироты `02-thermal.png`, `extracted-03.png` и дубликаты
  `extracted-04/05/06` — только перечислены в §0; удаление — отдельное
  решение владельца.

## 4. Критерии приёмки

- Ни в одной иллюстрации не срезан посередине текст, поле или шаг; степперы
  показывают все 5 шагов целиком.
- Все 4 статусбара: только полоса статуса, без мусора сверху, пустой хвост
  ≤16px, единая высота; текст читается в карточке `.sb-card` и в колонке
  `.two-col` без мельчания.
- `python docs/manual/build_manual.py` на LFS-указателе завершается ошибкой
  с именем файла и подсказкой (проверка вручную подменой одного файла).
- Все 29 инлайнов вычитаны глазами; `dotnet test` зелёный.
- Каждый кроп воспроизводится командой `python tools/manual-crops.py`
  из файла-источника в репо (ручные кропы вне репо больше не нужны).

## 6. Оценка

Волны 0–1 — ~15 минут; волна 2 — ~1 час (координаты по уже изученным
скринам); волна 3 — ~30 минут при запущенном приложении; волны 4–5 —
~40 минут. Итого около половины сессии.
