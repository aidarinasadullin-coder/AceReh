3.1 Автосохранение и восстановление сессии

Пункт 3.1 очереди 3 роадмапа post-1.8 · Идея №8 · снапшот в формате .smc — тот же wire, отдельный канал · хранение рядом с настройками (инфраструктура AppSettings) · ретеншн — одна копия
План: docs/plans/2026-09-21-autosave-plan.md · state ownership без изменений · ключей AppSettings нет · ADR не требуется
АВТОСЕЙВ — ТОЛЬКО ЧТЕНИЕ КАНОНА И СЛУЖЕБНЫЙ ФАЙЛ. Запись идёт через тот же IProjectSaveService (wire v1.1, атомарная запись tmp→move), MarkClean автосейв не делает — «звёздочка» и подтверждение закрытия не трогаются. Восстановленный проект не привязан к служебному файлу: «Сохранить» предложит выбрать путь.

Показывается после сплэша и до «Что нового» (модальный диалог из Loaded повис бы под Topmost-сплэшем — урок чека R-2026-09-21-02). Не показывается при запуске с .smc из проводника: признак «старт без файла» берётся в App.OnStartup у аргументов командной строки, а не у обнуляемого InitialProjectPath. Кнопки мока иллюстративны — реально стандартные Да/Нет контракта IDialogService (YesNo/Question). Диалог с меткой времени dd.MM.yyyy HH:mm. После «Да» проект помечается dirty: «звёздочка», промпт закрытия и автосейв продолжают работать — восстановленное нигде не сохранено.

Служебный каталог (рядом с settings.json)

settings.json — настройки; ключей автосейва нет
autosave.smc — единственный снапшот (формат .smc, wire v1.1)
autosave.smc.bak — предыдущая запись (артефакт атомарной записи), гасится вместе
Мой проект.smc — документы пользователя, автосейв их не трогает
Путь резолвится той же инфраструктурой SNOWCALC_SETTINGS_DIR, что и настройки — тестовая изоляция бесплатно. Остатки .tmp чистятся при старте. Крах во время записи невозможен наполовину: запись атомарна, при бое файл остаётся предыдущим.

Инварианты: .smc wire не меняется · канон только читается · writers не расширяются (MarkDirty после restore — санкционированный WI-5) · ключей settings.json нет · ADR не требуется (владение состоянием не меняется). Тесты: политика файла + предикат + восстановление (битый файл → удалить, MRU «не содержит», CurrentFilePath остался null) + полный зелёный прогон. UiSmoke-фикстура чистит autosave-файлы песочницы перед Launch (S10). Ручной smoke: 3 мин работы → файл появился; штатное закрытие → исчез; kill с dirty → старт → «Да» → данные на месте (проект dirty), «Сохранить» открывает SaveAs, закрытие спрашивает подтверждение; «Нет» → файл удалён; битый файл → ошибка и продолжение; старт с .smc из проводника → промпта нет.
