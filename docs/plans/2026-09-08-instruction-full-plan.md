# План: полная пользовательская инструкция (offline HTML-мануал)

**Дата:** 2026-09-08. **Статус:** план к выполнению по явной команде владельца.
**База:** приложение v1.1.2 (степпер 5 шагов), полировка ПЗ (план
`2026-09-07-pz-polish-plan.md`) идёт параллельно — см. §2 «Синхронизация».
**Тип работ:** docs+media-only. Код приложения, тесты и `data/` не трогаются.

## 0. Диагноз (сверка фактов: код + существующая инструкция)

Существующая «Инструкция короткая» (`docs/Инструкция короткая/README.html`)
покрывает 5 шагов с GIF, но не документирует существующие слои продукта:

1. **Индикаторы:** статус-бар (цветная плашка модуля по
   `CurrentStatusKind` Success/Warning/Error/Info, текст валидации
   `CurrentValidationText`, правый слот «⟳ пересчёт»), бейджи шагов
   (✓/●/⚠/⟳), `*` несохранённых изменений в заголовке, оверлей
   «Выполняется расчёт…», статусы экспорта в Результатах — в инструкции
   раздела нет.
2. **Проекты:** `.smc` (JSON, атомарная запись, `.bak`), Ctrl+N/O/S,
   Ctrl+Shift+S, двойной клик по файлу, номер/объект проекта в шапке,
   поведение при переносе на другой ПК (DEC-006: каталоги в `.smc` не едут;
   слой с отсутствующим в каталоге материалом → диалог «Импортировать из
   снимка?», без снимка — ошибка; финальная формулировка — по живому
   прогону I0).
3. **Отчёты:** сплит-кнопка «Отчёт PDF ▾» — 5 пунктов, включая ПЗ
   рабочий/холодный пуск; статусы «PDF сохранён: …».
4. **Справочники:** 9 встроенных материалов (`data/materials_db.json`,
   λА/λБ, ограничения «бетон ≤ 50 °C подачи», «асфальт ≥ −15 °C»),
   3 встроенных шаблона (`%LocalAppData%\SnowMeltingCalculator\data\
   construction_templates.json`), редакторы материалов/шаблонов (встроенные
   read-only; пользовательский материал не удаляется, пока используется),
   «Применить» заменяет пирог целиком, УГВ-порог λБ: < 1,0 м, только слои
   под трубой. Плюс риск: пользовательские материалы хранятся рядом с exe
   (в Program Files затираются при переустановке).
5. **Мелочи UX:** Ctrl+B (степпер), Escape в поле (откат значения),
   точка/запятая равнозначны, правая панель «Сводка проекта» видна при
   ширине ≥ 1680 px.

«Круче» — форма: поиск, темы, интерактивная карта окна, мини-конструктор
пирога, диагностические карточки, печать в PDF.

## 0.1 Решения владельца (согласование 2026-09-08)

| ID | Решение |
| --- | --- |
| В1 | Формат — **один offline HTML + папка `media/`**, в `docs/Инструкция полная/`. Старая «Инструкция короткая» не трогается. Сразу полный документ — **без прототипа**; реализация стартует по явной команде владельца |
| В2 | Медиа — **программный захват агентом** (скриншоты + кадры, GIF собирается энкодером). ScreenToGif — инструмент ручной ретуши владельца, в автоматический конвейер не входит. GIF ≤ 12 с, fps ≈ 10; там, где анимация не добавляет смысла, — статичный кадр с обводкой/стрелкой |
| В3 | Демо-проект эталонный — придумывает агент и **прогоняет в приложении**; все цифры в инструкции — из реального прогона (сверка 1:1). Базовый сценарий: Москва, «Парковка у ТЦ», шаблон «Парковка / площадка — бетон», УГВ ≥ 1 м, режим «Таяние», RAUTHERM S 17×2.0, шаг 200 мм, этиленгликоль 40 %, 3–4 контура (число уточняется по Δp ≤ 320 мбар) |
| В4 | Структура — 11 разделов (§1 плана, этап I3–I6). Фичи файла: клиентский поиск, светлая/тёмная тема, lightbox, чек-лист с localStorage, kbd-стиль хоткеев, стили печати (Ctrl+P → аккуратный PDF) |
| В5 | Мини-конструктор пирога в HTML: 9 материалов с реальными λА/λБ из `data/materials_db.json`, тумблер УГВ (< 1 м / ≥ 1 м — меняет λ только слоёв под трубой), живой расчёт R = d/λ и итоговых R₁/R₂, валидации как в программе (стяжка ≥ 40 мм, слой ≤ 1000 мм), 3 пресета («без утеплителя», «+ ЭППС 80», «мокрый грунт»), дисклеймер об упрощённости. λE в демке **не** показывается |
| В6 | Полный план вместо прототипа-пруфа; работа по этапам I0–I7 — по команде владельца |
| В7 | Синхронизация с ПЗ (SYNC-1): UI-скриншоты не зависят от полировки ПЗ (та меняет только PDF-рендеры отчётов) и снимаются из свежей сборки рабочего дерева. Скриншоты **экспортных PDF (ПЗ рабочий/холодный)** снимаются после завершения P-фаз ПЗ либо, по команде владельца, на текущем состоянии с пометкой ревизии в подписи |
| В8 | Ревью плана — независимая read-only проверка субагентом до старта работ; замечания фиксируются в §5 этого плана |

## 0.2 Рамки и предусловия

- **Не трогаем:** `src/`, `tests/`, `data/`, `installer/`, `docs/Инструкция
  короткая/`, `.smc`-контракт, краткий PDF. Кода нет —
  `ArchitectureRulesTests` затрагиваются только фактом отсутствия диффа.
- **Создаём:** `docs/plans/2026-09-08-instruction-full-plan.md` (этот файл);
  `docs/Инструкция полная/README.html` + `docs/Инструкция полная/media/`
  (скриншоты, GIF, спрайты) + `docs/Инструкция полная/evidence/`
  (прогоны, инвентарь медиа, лог сверки цифр).
- **Предусловия:** перед съёмкой — `dotnet build` рабочего дерева зелёный
  (текущее незакоммиченное состояние ПЗ по правилам репо buildable).
  Локаль ru-RU (числа с запятой) — как в приложении.
- **Запрещено:** внешние CDN/шрифты/аналитика в HTML (полный offline);
  документировать невоспроизводимое (исторический «баг шага укладки» из
  старой инструкции проверяется прогоном в I0 — фиксируется только живое
  поведение); «попутные» правки кода.
- **Якоря — по символам/фактам**, скриншоты подписываются версией сборки.

## 1. Этапы

Состав документа — **11 разделов** (нумерация для AC-2 и выходов этапов):

1. Герой; 2. Быстрый старт (включая подраздел «Установка и первый запуск»);
3. Карта окна; 4. Шаги 1–5 подробно; 5. Справочники (материалы, шаблоны,
мини-конструктор, хранение данных); 6. Индикаторы; 7. Проекты (.smc);
8. Отчёты и экспорт (включая экран «Результаты»); 9. Диагностика;
10. Справочные таблицы; 11. Чек-лист.

### I0. Подготовка и эталонный прогон (S)

- Сборка приложения, запуск, прохождение демо-проекта В3 по всем 5 шагам
  с фиксацией всех выдаваемых цифр в `evidence/demo-run.md` (таблица
  «ввод → вывод» для каждого шага).
- Подбор числа контуров по критерию Δp ≤ 320 мбар (рабочий режим); финал
  фиксируется как эталон В3.
- Проверка «бага шага укладки» (воспроизводится / нет) — запись в evidence.
- Прогон переноса: проект с пользовательским материалом/шаблоном
  сохраняется и открывается на «чистом» каталоге (временное переименование
  файлов каталогов) — фактические диалоги фиксируются для раздела 7.
- Фиксация baseline рабочего дерева: вывод `git status` сохраняется в
  `evidence/baseline-git-status.txt` (для AC-9).
- Согласование с владельцем итоговых демо-данных (номер/объект проекта —
  по умолчанию № 2026-117 «Парковка у ТЦ»).
- Выход: `evidence/demo-run.md` = единственный источник цифр для всего
  документа (AC-3).

### I1. Каркас HTML (M)

- Layout: сайдбар-оглавление с активной подсветкой, «хлебные» переходы
  шаг↔шаг, кнопка «наверх».
- Поиск: индекс **инлайн в HTML** (массив в `<script>`); fetch/XHR-подгрузок
  нет — на `file://` они блокируются браузером.
- Темы: светлая/тёмная + авто (`prefers-color-scheme`), переключатель,
  выбор в localStorage.
- Lightbox для скриншотов/GIF; kbd-стиль хоткеев; `@media print` (форсирует
  светлую тему независимо от активной).
- Чек-лист: галочки в localStorage под ключами с префиксом-ревизией
  `ace-manual-r1-*` (новая ревизия мануала не наследует старые галочки);
  весь доступ через try/catch — без localStorage документ работает,
  галочки просто не запоминаются.
- Выход: каркас на рыбе, открывается офлайн с `file://`.

### I2. Медиа-съёмка (M/L)

- Скриншоты: главный экран (для карты окна — широкий, ≥ 1680 px, с видимой
  сводкой), все 5 шагов в ключевых состояниях, диалоги (сохранение,
  редакторы материалов/шаблонов, «О программе»), результаты, отчёты.
  **Образцы экспортных отчётов (ПЗ) — по SYNC-1 (В7), не раньше.**
- Спрайты UI (вырезки): плашки статус-бара 4 цветов, бейджи ✓/●/⚠/⟳,
  кнопки «Рассчитать»/«Отчёт PDF ▾», статусные строки экспорта.
- GIF-сценарии (черновой список, финал — по инвентарю): выбор города;
  ручная корректировка климата; применение шаблона; создание материала;
  сборка и применение своего шаблона; смена режима и пересчёт; заполнение
  контуров; переключение рабочий/расчётный режим; сохранение проекта;
  экспорт PDF; полный цикл для героя (ускоренный).
- Сборка GIF программно (fps ≈ 10, ≤ 12 с), оптимизация веса; бюджеты:
  GIF-герой ≤ 4 МБ, остальные GIF ≤ 1–1,5 МБ, скриншоты PNG со сжатием,
  README.html с инлайн-индексом — мягкий бюджет ≤ 2 МБ; при превышении —
  fps/число кадров вниз, вместо повторных GIF — спрайты. Инвентарь
  `media/manifest.md` (файл → раздел → что показывает).
- Выход: `media/` с манифестом; суммарный вес ≤ 20 МБ (AC-4).

### I3. Контент: герой, быстрый старт, шаги 1–5 (L)

- Герой: GIF полного цикла, «Начать быстрый старт».
- Быстрый старт: подраздел «Установка и первый запуск» (системные
  требования Windows x64 / .NET 8, установка или портативная версия по
  `INSTALL.md`, сплэш → welcome «Начать работу», открытие `.smc` из
  проводника); карточка демо-проекта (таблица всех вводимых значений +
  дисклеймер «цифры — иллюстрация на эталонных данных»), прогресс-полоса
  с таймингом, 6 шагов по шаблону «GIF → таблица „Введите“ → „Что
  посчиталось“ (цифры из I0) → спрайт статус-бара → свёрнутое „Если не
  так“», финальная сводка + ссылки вглубь.
- Шаги 1–5 подробно: каждое поле (диапазоны, единицы, что влияет),
  ограничения материалов (бетон — ограничение **температуры подачи**
  ≤ 50 °C; асфальт — ограничение **температуры наружного воздуха**
  ≥ −15 °C), таблица автоподбора коллектора/Kv, подсветка R > 300 Па/м,
  рабочая/расчётная температура.
- Выход: разделы 1–4 по составу выше.

### I4. Справочники (M)

- Каталог 9 материалов (λА/λБ, ограничения, категория) + поиск.
- SVG-разрезы 3 встроенных шаблонов (послойно, с толщинами; толстые слои —
  с пометкой «не в масштабе»).
- Мини-конструктор пирога (В5): JS без зависимостей, подсветка изменений
  при переключении УГВ, связка «где это в программе» у значений.
- Правила редакторов материалов: имя 1–100 символов, уникальное без учёта
  регистра; λА, λБ > 0 (верхнего предела нет); макс. t подачи −50…200 °C;
  мин. t нар. −60…50 °C; встроенные read-only; пользовательский материал
  не удаляется, пока используется в шаблонах или текущей конструкции.
- Блок «Где хранятся ваши данные»: материалы — рядом с exe (предупреждение
  про переустановку в Program Files), шаблоны — `%LocalAppData%` (переживает
  переустановку, не переносится сам), `.smc` каталоги не содержит (DEC-006,
  поведение при переносе). Совет: копия `materials_db.json` перед
  переустановкой; перенос на другой ПК — оба JSON.
- Выход: раздел 5.

### I5. Индикаторы, проекты, отчёты (M)

- Индикаторы: легенда статус-бара (цвет → смысл), бейджи, `*`, оверлей,
  статусы экспорта — со спрайтами из I2; деталь легенды: правый слот
  «⟳ пересчёт» показывается только когда активный шаг — не «Тепловой
  расчёт».
- Проекты: создать/открыть/сохранить/сохранить как, `.bak`, двойной клик,
  подтверждение при закрытии с несохранёнными; поведение при переносе на
  другой ПК — по факту прогона I0.
- Отчёты: все 5 пунктов «Отчёт PDF ▾»; экран «Результаты» (сводка,
  гидравлика по коллекторам, оборудование, исходные данные) описывается
  здесь же. **SYNC-1 (В7)** — скриншоты ПЗ снимаются после завершения
  P-фаз ПЗ (или на текущем состоянии с пометкой ревизии по решению
  владельца).
- Выход: разделы 6–8.

### I6. Диагностика, справочники данных, карта окна (M)

- Диагностические карточки «симптом → причина → решение» с поиском:
  жёлтый/красный статус-бар, «⟳ пересчёт», R > 300 Па/м — **с оговоркой
  «только рабочий режим; при холодном пуске превышение штатно»**,
  Δp > 320 мбар, T_обратки < 0 °C, v вне 0,1–2,0 м/с, длина контура
  > 120 м (Ø20), ошибки экспорта (все три формулировки: «Невозможно
  экспортировать…», «Невозможно создать предпросмотр…», «Невозможно
  напечатать…»).
- Справочные таблицы: хоткеи (kbd), пороги (Kv/коллекторы, 300 Па/м
  (рабочий режим), 320 мбар, стяжка: **40 мм — проверяет программа,
  50 мм — рекомендация при нагрузках (не валидация)**, бетон ≤ 50 °C
  подачи, асфальт ≥ −15 °C наружного воздуха), диапазоны всех полей.
- Карта окна: скриншот с hotspot'ами, клик → раздел.
- Выход: разделы 9–10 и 3 (карта), финализация чек-листа (11).

### I7. Приёмка (S)

- Самопроверка: offline с `file://` (без сети), обе темы, поиск, печать
  Ctrl+P в PDF **из обеих тем**, вес `media/`, **агент сверяет 100 % цифр
  быстрого старта с `evidence/demo-run.md`** (AC-3), пробег
  демо-сценария «глазами новичка», **проверка минимум в двух браузерах
  (Edge/Chrome + Firefox)**.
- Ревью владельца; правки; фиксация ревизии в шапке README.html.

## 2. Правила процесса (параллельность с ПЗ)

- Работы **docs+media-only** — с полировкой ПЗ не пересекаются по файлам:
  конфликтов в git нет (этот план и `docs/Инструкция полная/` не
  соприкасаются с `src/`, `tests/`, `docs/report-spec-v2.md`).
- Съёмка UI не зависит от ПЗ-полировки; единственная точка синхронизации —
  **SYNC-1** для скриншотов экспортных PDF (В7). Очередность: после
  handover/коммита P-фаз ПЗ либо по явной команде владельца на текущем
  состоянии с пометкой ревизии в подписи.
- Перед съёмкой — свежая зелёная сборка рабочего дерева.
- Ничего не коммитится до ревью владельца (правило репо): handover —
  buildable дерево без изменений кода, новый контент в рабочем дереве.
- Каждый этап завершается записью в evidence (что сделано, чем проверено).
