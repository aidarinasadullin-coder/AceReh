## 3. Целевая схема

```
РЕХАУ_брендбук_2026.pdf (78 стр., стр. 13–32, 74)
        │  постраничная сверка (выполнена 2026-09-14)
        ▼
brand/tokens.json ──► brand/brand-rules.md (человекочитаемый свод)
        │                      │
        ▼                      ▼
  генераторы конвейера    skill/reference.md (rehau-deck)
  (rehau-kit.mjs,         ──► машинные бренд-чеки
   gen_*.py)                  (brand-verify)
```

Один канон → два потребителя (генераторы, скилл) → машинная проверка.

## 4. Фазы и критерии приёмки

### Фаза A — канон

- Новые файлы: `Презентация/harness-assets/brand/tokens.json`
  (машиночитаемый: цвета, градиенты, шрифты, логотип, сетка) и
  `brand/brand-rules.md` (человекочитаемый свод; каждое правило —
  страница-источник и модальность: запрет / рекомендация / осознанное
  отступление).
- Состав канона. Ядро сверено по страницам визуально (13–16, 19–21, 28,
  29, 32, 74); фирменная графика сверена косвенно (apply-файл ↔
  `rehau-kit.mjs`) — фаза A включает постраничную сверку остального:
  палитра — основные (стр. 13), серые `E4E4E4/B0B0B0/818181/4E4E4E`
  (стр. 14), доп. ветки + правило «≤ 10% цветового ряда» (стр. 15);
  градиенты — 4 канонических, «не рекомендуется более одного активного в
  области» (стр. 16) + недопустимые градиенты (стр. 17) как запреты;
  типографика — Inter, 6 начертаний, без курсива, роли начертаний
  (стр. 19, 21), регистры бренда/продуктов/линеек (стр. 8, 20); логотип —
  версии и правила фона (стр. 6, 9), охранное поле (стр. 7), запреты
  искажения (стр. 10), высота 15% короткой стороны, позиции (стр. 28);
  сетка 5:5, отступ = высота «Р» (стр. 29); QR (стр. 32); фирменная
  графика — элементы (стр. 41–44), плашки-скосы (стр. 55–57), паттерны
  (стр. 59–62), боксы и рамки (стр. 64–67); роли слайдов по стр. 74
  (титул: цветная панель + плашка-скос + логотип в правом верхнем +
  «2026»; контент: фото + цветная/тёмная панель, KPI-плашки-скосы,
  логотип внизу слева); русский текст — «РЕХАУ» кириллицей (решение
  владельца 2026-09-13, стр. 8); exceptions-лист (имитации терминала,
  решение №1).
- Шаг сверки (страницы, не читанные в ревью 2026-09-14): слоган
  (стр. 24–26) — включить в канон или зафиксировать «в 2026 не
  используется»; дополнительный шрифт (стр. 22) — и на его основе судьба
  Arial в `rehau-kit.mjs`; принципы композиции (стр. 30–31); охранное
  поле (стр. 7), недопустимое использование логотипа (стр. 10),
  недопустимые градиенты (стр. 17) — перенос запретов в канон;
  постраничная сверка фирменной графики (41–47, 55–67); сверка нумерации
  ссылок в правилах (цветные рамки: apply-файл цитирует стр. 66, TOC —
  стр. 67).
- Критерий: каждое правило канона имеет page-ссылку и модальность;
  tokens.json валидируется тривиальным скриптом (все HEX 6-значные,
  множества цветов = ожидаемым спискам из ревью).

### Фаза B — ремонт слоя правил и конвейера

- `rehau_2026_assets/palette.json` и `brand.css`: серые → стр. 14
  (`333333/666666/D9D9D9` выводятся), статус «incidental» → «corrected p.14».
- `brand_rules.md`: архивный баннер (решение №2).
- `rehau-kit.mjs`: шапка → ссылка на канон; `g20` → `E4E4E4`, добавить
  `g100`, `paper` → удалить или заменить (по решению №1); `LOGO_H` 0.10 →
  0.15; комментарий margin → «высота буквы Р».
- `build-pptx.js`: «REHAU ·» → «РЕХАУ ·», `INK` `1D1D1B` → `000000`,
  нейтрали по решению №1.
- `gen_schemes.py`: `INK` → `000000`, `MUTED` → `4E4E4E`, `LINE` →
  `E4E4E4`, `PALE`/`DARK` — по решению №1; терминальная имитация не
  трогается (exceptions).
- План pptx-qa-скилла: строка фазы C переписывается на «токены — из
  канона brand-canon» (правка одной строки, дрейфовые значения отозваны).
- Критерий: grep по конвейерным py/js не находит отозванных значений
  (`1D1D1B`, `6E6E73`, `C9C9CE`, `D9D9D9`, `333333`, `666666`, `F3F3F3`,
  `MiSans`, латинское `REHAU` в ru-строках) вне exceptions-списка;
  пересборка `harness-deck.html`/схем не требуется до следующего изменения
  деки (сданная дека не трогается).

### Фаза C — машинные бренд-чеки

- Новый `brand_verify.py` (или режим `--brand` в `verify_pptx.py` фазы A
  pptx-qa-плана — решается при его реализации): whitelist HEX в slide-XML
  (из tokens.json), запрет курсива (`i="1"`) вне exceptions, латинское
  «REHAU» в русских текстах, присутствие `MiSans`/`Segoe UI` в текстовых
  run'ах, высота логотипа 15% ±10% (кроме ролей стр. 74, где логотип
  меньше), совпадение заливок с палитрой.
- Реестр «правило → проверка» (`docs/agents/`) пополняется бренд-правилами.
- Критерий: `brand_verify` зелёный на пересобранной по канону деке;
  намеренно испорченная копия (не-брендовый HEX, курсив, «REHAU»
  латиницей) ловится с внятным отчётом.

### Фаза D — сборка скилла rehau-deck

- Выполняется как фаза C плана
  [2026-09-14-pptx-qa-skill-plan.md](2026-09-14-pptx-qa-skill-plan.md),
  предусловие — фазы A–C этого плана.
- `skill/reference.md` генерируется из tokens.json скриптом (или сверяется
  с ним при изменении — урок №27 по духу): ручной набор токенов исключён.
- Критерий: критерии фазы C pptx-qa-плана + сверка reference.md с каноном.

## 6. Что не меняется / не-цели

- Продуктовый код C#/WPF, state ownership, формат `.smc`, инварианты R1–R6 —
  не затрагиваются; handover каждой фазы фиксирует «state ownership
  без изменений».
- `brandbook-2026-application.md` (свод UI-приложения) не переписывается
  целиком: точечные правки A6/A7 и §5.6 вносятся одной правкой с пометкой,
  остальное остаётся документацией UI.
- Сданная дека `harness-deck-v2.pptx` и `harness-deck.html` не пересобираются.
- Универсальный скилл `document-skills:pptx` не трогается.
- Не-цели (дополнено 2026-09-14, вторая итерация сверки): после чтения
  оставшихся правило-несущих страниц в канон усвоены также внутренние
  проекты (11), кобрендинг (34–36), фото (38–39), прозрачность (49–51),
  волны (52–54), соцсети (68), иконки (70), иллюстрации (72). Остались
  только носители, не относящиеся к декам — печатные материалы, билборд,
  roll-up (75–77) — и встраивание шрифтов в PPTX (открытый вопрос,
  фиксируется в каноне); judge-субагент.
- Открытая задача ассетов (найдено при чистке 2026-09-14): белый логотип
  и паттерны black/red-bg в `rehau_2026_assets` отсутствуют (манифест:
  missing) — доизвлечь из PDF (стр. 9 и 63), затем перенаправить
  `logo_white` в `docs/workspace/scripts/*.mjs` с `rehau_assets/` на
  `rehau_2026_assets/` и удалить `rehau_assets/` целиком. До этого
  `rehau_assets/logo_white.png` — единственный живой источник белого
  логотипа. Старый гайдлайн удалён: `brand_rules.md`,
  `rehau_guideline.pdf`, `brandbook_text.txt`, `extract_assets.py`.

## 7. Риски

| Риск | Митигация |
|---|---|
| Правки серых/шрифтов меняют вид готовых схем деки | Дека не пересобирается до следующего изменения; визуальная приёмка — при первой пересборке (рендер-гейт pptx-qa-плана) |
| F5F5F6/4E4E4E-замены ухудшат читаемость схем | Приёмка фазы B включает рендер схем до/после; откат отдельного значения — через exceptions |
| Канон разойдётся с reference.md скилла | reference.md генерируется из tokens.json (фаза D), ручной набор исключён |
| Слоган-2026 отличается от «Ваше преимущество РЕХАУ» | Шаг сверки стр. 24–26 в фазе A, до включения в канон |
| brand-чеки дают ложные срабатывания (латиница в кодовых именах, URL) | Whitelist-подход: проверка только текстовых run'ов, исключения — tokens.json `exceptions` |

## 8. show-me

[show-me-brand-canon.html](show-me-brand-canon.html) — самодостаточный
артефакт в REHAU-токенах, построен из реальных сущностей плана: находки

## 9. Эффект

- Один непротиворечивый канон 2026 вместо трёх конкурирующих сводов;
  каждое правило — со страницей-источником и модальностью.
- Конвейер и скилл собирают деки из канона; дрейф токенов ловится
  машинно, а не на приёмке владельцем.
- Скилл rehau-deck получает сильный reference.md: бренд-правила, которые
