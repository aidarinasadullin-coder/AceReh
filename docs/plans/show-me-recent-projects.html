Схема ключей AppSettings — фиксируется планом 1.2 для очереди

settings.json — новый ключ (реальная сущность)

{
  "IsSidebarCollapsed": false,
  "RecentProjects": [
    "D:\\Проекты\\Парковка ТЦ Москва.smc",
    "D:\\Проекты\\Площадь у вокзала.smc"
  ]
}
Свойство List<string> RecentProjects = new(), newest-first. Отсутствие ключа = дефолт (JsonSerializer). Битый null в JSON гасится GetListSafe() — NRE невозможен.

Конвенция для 1.3 и 3.1 (условие роадмапа)

1. Каждый пункт очереди добавляет свои свойства в AppSettings — переименование и смена семантики чужих ключей запрещены.

2. Миграций нет: отсутствие ключа = значение по умолчанию.

3. Ожидаемые будущие ключи: 1.3 — WhatsNewShownVersion (окончательно — план 1.3), 3.1 — префикс Autosave* (план 3.1).

Инварианты и риски

Не меняется

State ownership (владельцы те же) · .smc wire · writers-канон (ADR не нужен) · undo-дневник (открытие уже стирает историю — ADR-014) · SplashWindow

Осознанные риски

Недоступный сетевой путь может замедлить открытие подменю (File.Exists, ≤10 записей) · файл удалён после построения меню → существующий диалог ошибки

Гейты handover

Полный зелёный dotnet test · пересборка инструкции (ManualVersionGateTests) · ручной smoke: drag, подменю, рестарт, очистка, битый файл
Процесс: атакующее ревью плана (вектора A1–A8, урок №26) → чек в docs/reviews/ → сигнал владельца → реализация → handover (незакоммиченное дерево + зелёный dotnet test). show-me регенерируется из плана (урок №27) — не править руками. Токены — канон REHAU (#E50040 / #4FC7B5 / #1D1D1B / серые).
