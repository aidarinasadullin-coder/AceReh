# План: полировка пояснительной записки (точность чисел, формулы, гликоль, словарь)

**Дата:** 2026-09-07. **Статус:** план к выполнению по явной команде владельца.
**Спецификация:** `docs/report-spec-v2.md` (принята; настоящая мини-фаза
дополняет её журнал решений).
**База:** отчёт v2 (Markdown R0–R8) + мини-фаза PDF-PZ — реализованы и
приняты; краткий PDF v1 и `.smc` не изменяются.

## 0. Диагноз (ревизия 2026-09-07, визуальная приёмка pdf-pz + разбор кода)

1. **Точность чисел:** единый жёсткий `TableFormat = "N3"`
   (`CalculationReportMarkdownRenderHelper.cs`, константа, импортируется
   PDF-рендером) применяется ко всем табличным ячейкам и «Результатам»
   шагов: «1,000 шт», «110,000 м», «6 700,000 Вт». Округление живёт только
   в рендере; домен и каноника хранят полные `double`.
2. **Корни:** конвертер `CalculationReportLaTeXFormulaRenderer.TryConvertToLaTeX`
   не переводит `√(…)`/`sqrt(…)` в `\sqrt{…}` — CSharpMath рисует голый глиф
   радикала без винкулы; ASCII `sqrt(…)` в приложении формул — курсивные
   буквы. PNG рендерится с прореживанием 2× и запасом канвы ~4em над базовой
   линией.
3. **Вёрстка формул:** PNG обрезается по контенту (pad 2px) и кладётся на
   базовую линию абзаца (`SpaceAfter = 2pt`, `LeftIndent = 12pt`) — вертикальный
   ритм «плавает»; формулы прижаты влево, нумерации нет.
4. **Свойства теплоносителя:** `HydraulicsSectionBuilder` вписывает заглушки
   `0.0` для плотности/теплоёмкости/вязкости → рендер честно показывает
   «нет данных» (правило В2). При этом `CircuitsCalculator` уже получает эти
   свойства из `GlycolDataService` (база `data/glycol_data.json`, ASHRAE) и
   считает от них гидравлику — свойства являются входом расчёта и не
   сохраняются.
5. **Дросселирование:** считается и сохраняется (`Throttling`,
   `HydraulicsPersistenceMapper`), но валидный ноль референсного контура
   прогоняется через правило «0 → нет данных».
6. **Обозначения:** в ПЗ просачиваются кодовые идентификаторы (`PowerUp`,
   `RFb`, `JHmü`, `zu_dr.`); заголовки таблиц расходятся с глоссарием Ф3
   («Потери в трубе» vs «Δp трубы, Па»).

## 0.2 Рамки и предусловия

- **Не трогаем:** `.smc` (wire-контракт, DEC-T08), краткий PDF
  (`Services/Results`), Markdown-экспорт как UI-путь (остаётся компонентом
  без UI), канонические входы, `ThermalCalculator` (расчёт не меняется).
- **Трогаем:** `Services/Reports/Calculation/**` (модель, билдеры, рендеры),
  гидравлический снимок (`Services/Project/HydraulicsStateSnapshots.cs` + точка
  его заполнения в пайплайне гидравлики), DI-регистрации.
- **Якоря — по символам**, не по строкам (правило плана v2, §0.1): ссылки на
  файлы:строки ниже индикативны.
- **Инварианты:** у каждого нового значения снимка один writable owner —
  гидравлический расчётный пайплайн; ПЗ остаётся Derived-читателем.
  `ArchitectureRulesTests` — зелёные на каждом этапе; если списки
  санкционированных writers снапшота фиксированы тестами — расширить вместе
  с ADR (P0).
- **Запрещено:** новые инженерные расчёты в ПЗ; изменение значений констант;
  правка `AppCulture`; дублирование интерполяции гликолей в билдере (билдер
  не вызывает `GlycolDataService` сам — см. P4).

### P1. Точность чисел — вариант Б (M)

- Модель: `ReportValue<T>` + `int? Decimals { get; init; }`; флаг
  `bool ZeroIsValid { get; init; }` (для P4/В14).
- Дефолт `TableFormat` в `CalculationReportMarkdownRenderHelper` → `"N2"`;
  рендеры (Markdown + PDF): `ReportNumber.Format(v.Value, v.Decimals ?? TableFormat)`;
  нулевое значение → «нет данных» только если `!v.ZeroIsValid`.
- Билдеры назначают `Decimals` каждой табличной `ReportValue<double>` по
  единице (таблица фиксируется в спеке §7.3): шт/контур → 0; мм/Вт/Па → 0;
  м/°C/м² → 1; кВт/м³/ч/л → 2; λ/R/ν/σ → по текущим правилам (не ухудшать);
  Re → 0; скорость → 2. Исключения сохраняются: константы расчёта — свои
  `Decimals`; λ в сравнении режимов — явный N3; подстановки — позначальные.
- Обороты клапана: рендерить дробью через существующий
  `ValveTurnsToFractionConverter` («8», «8 ½») вместо «8,000 об».
- Тесты: обновить пины форматов; **пин полноты** — в собранной модели
  `CalculationReportData` нет `ReportValue<double>` с `Value != null` и
  `Decimals == null`; детерминизм; регрессия Markdown.

### P2. Корни + PNG (S/M, один дифф рендера формул)

- `TryConvertToLaTeX`: правила `√( … )` → `\sqrt{ … }` и `sqrt( … )` →
  `\sqrt{ … }` (сканирование сбалансированных скобок, вложенность; применять
  после защиты индексов `d_нар`, чтобы подкоренные подстрочные группы не
  разъехались).
- Мелочь: убрать хвостовую точку в формуле Kv (`zu_dr./10⁵/ρ` → `zu_dr/10⁵/ρ`)
  в `HydraulicsSectionBuilder`.
- PNG: `PointPerPixel` 0.5 → ≈0.33 (3×); высота канвы и точка рисования —
  пропорционально, чтобы гарантировать запас над базовой линией ≥ 5em
  (сейчас ~4em); проверить, что `\sqrt{дробь}` не режется сверху/снизу.
- Тесты: `LaTeXConverter_*` (новые кейсы √ и sqrt, вложенные скобки);
  рендер формулы с `\sqrt{...}` — контроль размеров PNG; детерминизм.

### P3. Вёрстка формул в PDF (M)

- Шаги (`RenderStep`): формула по центру — безрамочная двухколоночная
  таблица: широкая ячейка (формула, `ParagraphFormat.Alignment = Center`)
  + узкая («(N)», `Alignment = Right`, вертикальное выравнивание ячеек —
  центр). Сквозной счётчик формул — поле экземпляра PDF-рендера.
- `SpaceAfter` формульного блока 2pt → 6pt (уточнить по приёмке образцов);
  `LeftIndent` на формульные абзацы не распространяется (центрирование).
- Приложение формул — справочник **без номеров** (нумеруются только формулы
  в теле документа).
- Тесты: детерминизм; пин «число номеров = число формул в теле»; визуальная
  приёмка по образцам.

### P4. Свойства гликолей — вариант А + дросселирование (M/L)

- Снимок: расширить гидравлический снимок (`HydraulicsStateSnapshots`) полями
  `GlycolProperties` для Operating и Design (ρ, c_p, ν; λ, Pr — бонусом).
  Заполнение — в пайплайне гидравлики в точке обновления снимка результатами
  (те же входы, что переданы в `CircuitsCalculator`: тип/концентрация из
  `HydraulicInputData`, `operatingTemperature`/`designTemperature` те же
  параметры). Сервис singleton — повторный `GetProperties` детерминирован и
  равен значениям расчёта; **пин**: снимок == `GetProperties(входы)`.
- Провайдер: расширить модель входа экспорта (по образцу `ThermalReportDetail`
  — например `HydraulicsReportDetail`): свойства из
  `ProjectSession.HydraulicsState.Snapshot` + флаг источника. Билдер
  `HydraulicsSectionBuilder` читает их вместо заглушек `0.0`
  (стр. 29–31); `FormulaStatusUnconfirmed` снять; источник колонки —
  «рассчитано программой»; в таблицу добавить теплопроводность и Pr (названия
  — из Ф3: «Теплопроводность», «Число Прандтля»).
- Fallback (В13): снимок не содержит свойств (файл старой версии) — ровно
  один контрольный вызов `GetProperties(тип, концентрация, T_режима)` по
  входам каноники, в ПЗ — примечание «свойства теплоносителя получены
  контрольной интерполяцией» (аналог §3.2); концентрация 0 % → свойства воды
  (уже реализовано в сервисе); выход за диапазон базы → «нет данных» +
  предупреждение (правило В2).
- Дросселирование (В14): в таблице контуров `Throttling` создаётся с
  `ZeroIsValid = true` → «0» вместо «нет данных»; референсный контур —
  существующее примечание «клапан полностью открыт» остаётся.
- Тесты: пин снимок==GetProperties; fallback-пометка (сценарий старого файла);
  дросселирование «0»; регрессия `ArchitectureRulesTests`, round-trip `.smc`.

## 2. Правила процесса

- Коммиты: P0 отдельно (docs); P1–P5 — по одному коммиту на атом, каждый —
  с зелёным тест-подмножеством; P6 — handover-коммит (перегенерированные
  образцы + сводка). Без owner-review не мержится (AGENTS.md).
- Порядок: P0 → P1 → P2 → P3 → P4 → P5 → P6. P2/P3 независимы от P1/P4/P5
  и могут выполняться параллельно при необходимости; P4 требует ADR из P0.
- **Материальная поверхность** (широкая правка слоя отчётов + новое поле
  канонического снимка): перед реализацией P3–P5 — один независимый
  read-only обзор диффов P1–P2 (прецедент ревью плана v2).
- Детерминизм ПЗ сохраняется на всех этапах (одинаковый проект+режим →
  идентичный вывод, кроме даты-параметра).
