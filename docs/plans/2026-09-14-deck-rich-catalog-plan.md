# План: rich-catalog — фирменный каталог ролей для скилла rehau-deck

> Дата: 2026-09-14. Статус: план на owner-ревью (G1), реализация не начата.
> Основание: дека B параллельной сессии
> (`docs/presentation/2026-09-14-snegotayanie-dlya-rukovodstva.pptx`)
> формально бренд-корректна (brand_verify — 0 находок), но бедна: 9
> контентных слайдов — одна роль «буллеты+скрин», нет панельных делений,
> плашек, градиентов. Причина: скилл v1 клонирует из рабочего шаблона
> владельца (5 скромных ролей), а богатство компоновок живёт в
> официальных шаблонах 07-2026 (69/70 ролей) — в скилл они не заведены.
> Изменение нематериальное (тулинг презентаций); ревью плана не
> назначается, владелец может запросить на G1. show-me:
> [show-me-rich-catalog.html](show-me-rich-catalog.html).

---

## 1. Мотивация

- Токены канона (`brand/tokens.json`) управляют цветом/шрифтом/логотипом —
  и соблюдаются. Похожесть на РЕХАУ определяется **словарём компоновок**,
  который живёт в шаблонах, а не в токенах.
- Рабочий шаблон владельца — 5 ролей без фирменных структурных зон.
  Официальные «Шаблоны презентации 2026» — 69/70 ролей: панельные деления,
  KPI-плитки, фото 60:40, разделители, карточки (превью-каталог снят:
  `.scratch/template-preview/`, светлая — 69, тёмная — 70).
- Официальные роли — **placeholder-based** (6–25 плейсхолдеров на слайд,
  пустые тексты): заливка контента должна идти по индексам плейсхолдеров,
  а не по именам шейпов, как в текущем `build_final.py`.

## 3. Фазы и критерии приёмки

### Фаза A — каталог ролей

- Инвентарь официального светлого шаблона: `python verify_pptx.py
  --inventory <Светлая_07-2026.pptx> --out catalog-light.json` (механика
  готова; дополнить инвентарь сохранением текстов-плейсхолдеров и типов).
- Contact-sheet: сетка миниатюр `catalog-light-sheet.png` (69 превью,
  подписанные номерами ролей) — коммитится; полные PNG — вне git.
- **Отбор 15–20 богатых ролей** по критериям: есть фирменная структурная
  зона (панель/скос/плашки/градиент/фото-зона), покрывают типовые типы
  контента (проблема, решение, цифры, сравнение, стадия, команда, вывод),
  заполняемы python-pptx. Агент предлагает по contact-sheet,
  **владелец утверждает список** (гейт G2a) → `deck-catalog.json`
  (роль: номер слайда, человекочитаемое имя, карта плейсхолдеров,
  бюджет-оценки).
- Критерий: у каждой выбранной роли — превью до заливки и мини-превью с
  тестовым контентом (рендер гейтом фазы B pptx-плана).

### Фаза B — карта «контент → роль» и правила композиции

- `reference.md` (генерация из канона расширяется): карта типов контента:
  проблема → панель-деление с фото; цифры/факты → KPI-плитки; этап/стадия
  → разделитель; сравнение → две колонки; вывод/CTA → цветная панель с
  градиентом; команда/контакты → карточки.
- Правила композиции (в SKILL.md): на каждом слайде минимум одна
  фирменная структурная зона (панель/плашка/градиент); чередование
  фокус-цветов красный/teal/тёмно-серый; одна роль ≤ 2 подряд; заголовок
  слайда — утверждение, не тема.
- Примитивы `rehau-kit.mjs` (параллелограмм, угловой акцент, градиентные
  панели, разделитель) — доступны агенту для достройки; не переписывать.
- Критерий: карта покрыта выбранными ролями (каждому типу контента — ≥1
  роль); правила внесены в SKILL.md; переустановка скилла.

### Фаза C — интеграция и приёмка

- `build_final.py`: параметр `--catalog deck-catalog.json` — заливка по
  плейсхолдерам выбранной роли; без параметров — прежнее поведение
  (дека проекта не меняется).
- Бюджеты ролей: из эталонных текстов роли; пустые плейсхолдеры — лимит
  из карты роли (зн./строка), проверить рендером.
- **Приёмочный критерий (G3)**: пересборка деки B
  «Снеготаяние для руководства» до/после — скошенные деления, плашки,
  цветовые фокусы и разнообразие ролей видны на превью; verify+brand
  зелёные; сравнение показывает владелец.

## 5. Что не меняется / не-цели

- Продуктовый код, state ownership, формат `.smc` — не затрагиваются.
- Существующая дека `harness-deck-v2.pptx` и её конвейер (быстрые правки
  существующих дек) — работают как раньше.
- Тёмный шаблон, генерация слайдов с нуля, judge как обязательный гейт,
  автогенерация текстов контента — не-цели v1.
- Рабочий шаблон владельца — только чтение.

## 6. Риски

| Риск | Митигация |
|---|---|
| Placeholder-заливка сложнее именной (layout vs slide placeholders) | Клон через zipfile сохраняет placeholder idx; обход рекурсивный; e2e на 3 ролях до полного прогона |
| Часть ролей с плотной векторной графикой — текстов мало | Отбор ролей с проверкой заполняемости (фаза A, мини-превью с тестовым контентом) |
| MiSans официального шаблона | Пост-обработка typeface → Inter уже есть, переносится |
| Theme официального шаблона отличается от рабочего | Клонируется вместе со слайдами; brand_verify ловит не-канон цвета |
| Скилл-дрейф (правка reference.md руками) | reference.md генерируется из tokens.json + карты ролей; перегенерация при изменении |
| Ложные находки бюджета на новых ролях | Бюджеты ролей — из карты роли; калибровка мини-превью в фазе A |

## 8. Эффект

- Деки собираются из того же словаря компоновок, что официальные шаблоны
  РЕХАУ: «близко не похоже» становится технически невозможным.
- Разнообразие — свойство конвейера, а не старание агента; бедные деки
  отсекаются правилом композиции и гейтами.
- Полный каталог (69/70 ролей) доступен декам без новой разработки:
  добавление роли = строка в catalog JSON.
