# План: новый дизайн PDF «Результаты расчёта» (концепция «Корешок + плитки»)

Дата: 2026-09-09. Статус: план согласован владельцем (выбор концепции — гибрид
A+B, приёмка макета и градиента стр. 16 — «супер! то что я хотел», 2026-09-09).

## 1. Контекст

Действующий экспорт результатов (`src/Services/Results/PdfExportService.cs`,
744 строки, MigraDoc/PDFsharp) не соответствует брендбуку REHAU 2026: сплошная
красная баннер-шапка, несанкционированная серая палитра, Arial, серые заливки
и зебра в таблицах. Прототип нового дизайна собран и принят владельцем:

- Прототип: `docs/workspace/pdf-results-proto/` (вне git, песочница) —
  `proto.pdf`, рендеры `proto-p1.png`/`proto-p2.png`, исходник `Program.cs`.
- Визуальный гейт: независимое ревью pass/pass по обеим страницам
  (контраст, палитра, типографика, грамматика).

Прототип отрисован тем же продакшн-стеком: MigraDoc/PDFsharp 6.2 +
`CalculationReportPdfFontBootstrapper` (Inter) + `PdfFlateStreamRepair`;
фон-корешок — SkiaSharp (пакет уже транзитивно в проекте через
CSharpMath.SkiaSharp, PDF-записка).

## 2. Дизайн-контракт (принят владельцем)

- Пирамида «Ответ → Спека → Обоснование»; правило «цифра живёт ровно в одном
  месте» (дедупликация: насос/бак/труба — только в спеке).
- Стр. 1 «Результаты расчёта»: герой q суммарная (красный, крупно) + свита
  (q↑/q↓, R над/под трубой) + зелёный статус подтверждения; 4 плитки
  теплотехники в цветах пиксель-иконки (красный/зелёный/тёмно-серый/серый);
  «Спека закупки и монтажа» — 6 строк.
- Стр. 2 «Обоснование и наладка»: притенённые справочные блоки (климат/режим/
  теплоноситель; слои конструкции), «Наладка · проверка холодного пуска»
  (15,46 → 83,83 кПа, красным; действие — дросселирование), полная таблица
  контуров с красной верхней рамкой, дроссель > 0 — красным.
- Корешок: фирменный градиент «Активный красный», светлый вариант
  (брендбук стр. 16): #E50040 держится в верхней ~38% высоты, книзу — белый;
  типографика по правилу стр. 16 — белый наверху, тёмный (#1D1D1B) на светлой
  нижней зоне. Белая версия знака «РЕХАУ» + оглавление-навигатор.
- Палитра строго: #E50040, #4FC7B5, #1D1D1B, #4E4E4E, #818181, #B0B0B0,
  #D9D9D9, белый. Числа — канон ru-RU (десятичная запятая, пробел-тысячи).
- Письмо бренда — кириллица «РЕХАУ» капсом (брендбук-2026 стр. 8; ранее
  brand_rules.md §3 содержал ошибку чтения «только латиница» — исправляется в
  песочнице отдельно, в этот план/коммит не входит).

## 3. Не-цели и инварианты

- ПЗ-записка (`src/Services/Reports/Calculation/*`) не трогается — прошла
  приёмку 19/19 (мини-фаза PDF-PZ); общие точки — только
  `CalculationReportPdfFontBootstrapper` (переиспользуется как есть).
- `IPdfExportService`, `ResultsPdfData*`, строители данных, DI-регистрация
  (`AddSingleton<IPdfExportService, PdfExportService>`) — без изменений.
- State ownership, persistence, .smc-формат — не затрагиваются; ADR не
  требуется (производный рендер, «state ownership без изменений»).
- Правила R1–R6/`ArchitectureRulesTests` — не затронуты (Services зависят
  только от модели данных ResultsPdfData, не от ViewModel).

## 4. Отличия от прототипа при переносе в прод (мультиколлекторность)

Прототип захардкожен на 1 коллектора / 2 страницы. Прод должен держать N
коллекторов (таблицы контуров растягиваются на страницы 2..N):

1. Подложек корешка — две, статичные, embedded-ресурсы:
   `rehau_spine_page1.png` (активны ОТВЕТ, СПЕКА) и `rehau_spine_page2.png`
   (активны КОНТУРЫ, ОБОСНОВАНИЕ, НАЛАДКА). Секция 1 → подложка 1, секция 2 →
   подложка 2; Primary-хедер секции 2 автоматически повторяет её на всех
   продолжениях.
2. Номер страницы — не в фоне (число страниц заранее неизвестно), а
   MigraDoc-полями в контентной зоне: `AddPageField() / AddNumPagesField()`
   в подвале каждой секции. Подвал — таблица с левой распоркой 180pt (правее
   корешка); контентная обёртка получает нижний резерв ~34pt, чтобы
   растягивающиеся таблицы не наезжали на подвал (при нулевых
   BottomMargin/FooterDistance полях, как в прототипе).
3. Цифры страниц у пунктов навигатора убираются (при N>2 они становятся
   ложью); остаются только пункты и белые черты активных.
4. Блок «Обоснование» рендерится один раз в начале секции 2; за ним — таблица
   контуров каждого коллектора (заголовок «Коллектор N · тип», итоговая
   строка) — при переносе на следующую страницу фон повторяется.
5. Блок «Наладка · проверка холодного пуска» при N коллекторов — по строке на
   каждый коллектор (рабочая `PressureLoss_Operating_kPa` → холодная
   `PressureLoss_Cold_kPa`, действие — максимальный `ZuDrosseln` по контурам
   этого коллектора с номером контура и оборотами); при одном коллекторе
   выглядит как в принятом макете.

(вне git); сами PNG — в git как ресурсы. Дополнительно в src добавляется
`Resources/Images/rehau_logo_white.png` (белая версия знака, чистое
извлечение брендбука) — фиксация источника в репо.

## 6. Риски

- `PdfFlateStreamRepair.RepairImageStreams` обязателен (подложки — image-потоки;
  без фикса Acrobat показывает «Недостаточно данных») — тестовый замок строгой
  валидации Adler-32 по образцу `ValidateImageStreamsStrictly`.
- `PageSetup` для второй секции нужно клонировать (MigraDoc требует Clone).
- Удержание заголовков при переносе: заголовок коллектора — параграф с
  `Format.KeepWithNext = true`; строка заголовков колонок таблицы контуров —
  `HeadingFormat = true` (повторяется на страницах 3+); «KeepWith простым
  порядком добавления» не существует — на MigraDoc не рассчитывать (находка
  ревью P1).
- Пустые строки данных (Проект/Объект) — печатать «—», не пустоту.
- Белый текст только на насыщенных плитках; на зелёной (#4FC7B5) — тёмный
  (контраст, замечание ревью).

## 7. Чеклист исполнения

1. Сгенерировать `rehau_spine_page1.png` / `rehau_spine_page2.png` и добавить
   `rehau_logo_white.png`; включить в csproj как Resource.
2. Переписать `PdfExportService.cs` на принятую композицию (данные из
   `ResultsPdfData`, ничего не хардкодим).
3. Обновить тесты (см. §5), прогнать `dotnet build` + `dotnet test` — зелёные.
4. Визуальная проверка: харнесс в `docs/workspace/pdf-results-proto` рендерит
   экспорт реального сервиса на fixture-данных; сверка с `proto.pdf`
   (композиция/палитра), мультиколлектор-фикстура (2 коллектора) — фон и
   нумерация не ломаются.
5. Handover: некоммиченное buildable-дерево, зелёный `dotnet test`, отчёт
   владельцу с записью «state ownership без изменений». Код коммитится только
   после ревью владельца.

## 8. Приёмка

- Экспортированный PDF соответствует принятому макету (стр. 1 — герой+плитки+
  спека; стр. 2+ — обоснование/наладка/контуры) с градиентным корешком.
- Все числа отчёта присутствуют ровно один раз; ru-RU канон сохранён.
- `dotnet test` зелёный; старый рендер отсутствует в кодовой базе
  (grep по артефактам старого дизайна: сплошной красной шапки-баннера нет).
