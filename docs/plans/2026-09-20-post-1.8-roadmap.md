### Сверка гликолевой базы с ASHRAE (выполнена 2026-09-20)

Метод: таблицы 6–13 извлечены из `AshraeFundamentals.pdf` (2009) программно,
по координатам слов (29 строк × 9 концентраций на таблицу, без ручного
перепечатывания), переведены в СИ (кг/м³ ×16.0185; кДж/кг·К ×4.1868;
Вт/м·К ×1.7307; вязкость lb/(фут·ч) → мм²/с через плотность) и сверены
ячейка-в-ячейку с `data/glycol_data.json`. Метаданные базы заявляют источник
«ASHRAE Handbook—Fundamentals (2009), Dow Chemical Tables» — **сверка это не
подтверждает**:

- **Теплоёмкость и теплопроводность (оба гликоля)** — под меткой концентрации
  «c %» лежит значение ASHRAE для «(c−20) %»: сдвиг колонок на две позиции
  (пример, PG, 21.1 °C: в базе 30 % → 4.080 кДж/кг·К, это в точности колонка
  10 % — 0.974 Btu×4.1868 = 4.078; верное значение 30 % — 3.852). Коэффициенты
  пересчёта единиц при этом применены верно. Следствие: cp завышен на
  +6…22 %, λ — на +12…50 %.
- **Вязкость (оба гликоля)** — тот же сдвиг колонок **плюс** сырые значения
  lb/(фут·ч) записаны как мм²/с без перевода в кинематическую (пример, PG,
  21.1 °C, «50 %»: в базе 7.11 — это в точности сырая ASHRAE 30 % = 7.11
  lb/(фут·ч); верные 6.05 мм²/с). Следствие: вязкость завышена на +9…45 %.
- **Плотность** — совпадает с ASHRAE (±0.15 %) только в полосе ≈ 0…+10 °C;
  в холодной зоне расхождение до +22 кг/м³, в строке −17.8 °C под метками
  40–60 % лежат значения колонок 70–90 % (±0.6). «Аномалия 60 % < 50 %» —
  артефакт этого сдвига: в самом ASHRAE строка 0 °F монотонна
  (66.23 < 66.68), есть только «родной» квирк источника 90 % < 80 %. 184
  ячейки ASHRAE в базе пусты, 21 ячейка базы вне диапазона ASHRAE.
- **Точки замерзания/кипения (Tables 4–5)** — выборочно верны (PG 5 % масс →
  −1.6 °C, 10 % → −3.3 °C — точное совпадение после перевода °F).
- Скрипт экстракции/сверки готов (извлечение по координатам + сравнение);
  предлагается коммитить как инструмент в рамках мини-плана 2.2
  (`scripts/verify-glycol-ashrae.py`, путь к PDF — параметр).

### Проверка «замёрзнет ли гликоль» — не реализуем (решение владельца 2026-09-20)

Пометка, почему нет: **нет решения, какую температуру брать для сравнения**.
Кандидаты — расчётная температура холодных суток t₀.₉₈ из климатической базы
города либо «минимальная ожидаемая температура системы» как отдельный входной
параметр объекта. ASHRAE (гл. 31) рекомендует концентрацию с точкой замерзания
на 5 °F (≈2.8 К) ниже минимальной ожидаемой температуры — то есть опирается на
параметр объекта, а не на климат города; перенос этого на методику (п. 11.13
`Formulas_Snegotayanie.md`) — решение владельца. Автоподбор минимальной
концентрации зависит от того же выбора и тоже в ожидании. Данные для обеих
фич готовы (кривые замерзания в базе верны).

## Правила для всех пунктов очередей

- **State ownership:** каждый план закрывает строкой «state ownership без
  изменений»; любое касание владения — только через ADR и отдельное решение
  владельца.
- **`.smc` wire** не меняется ни в одном пункте очередей 1–3.
- **AppSettings** расширяют пункты 1.2, 1.3, 3.1: схему ключей задаёт первый
  план очереди (1.2), остальные переиспользуют без конфликтов.
- **UI-правки** (все пункты очереди 1, частично 2.1/3.1) требуют пересборки
  инструкции `python docs/manual/build_manual.py` — гейт
  `ManualVersionGateTests`; по необходимости — пересъёмка затронутых
  иллюстраций (`docs/manual/tools/`).
- **Ревью** в атакующем режиме (вектора — урок №26); три ревью без находок —
  ротация векторов (журнал `docs/agents/quality-log.md`).
- **Уроки** → `docs/agents/lessons.md` + строка в `rules-registry.md` тем же
  коммитом (гейт `Registry_OwnerRulesAndLessons`).
- **CI:** красный `master` блокирует старт нового пункта.
