## 1. Мотивация

- Конвейер `Презентация/harness-assets/` собирает деки двумя путями:
  `build-pptx.js` (pptxgenjs с нуля, палитра REHAU) и `build_final.py`
  (клонирование 12 слайдов рабочего шаблона владельца на уровне OOXML через
  `zipfile` + заливка контента через python-pptx). Контроль качества —
  ручной: `pdf_preview_*.png`, `compare-font.png` сделаны руками.
- Главный риск `build_final.py` — regex-хирургия пакета: ручная пересборка
  `_rels/presentation.xml.rels`, `[Content_Types].xml`, `sldIdLst`
  (`build_final.py:30–55`). Файл может открываться в LibreOffice, но
  требовать «восстановления» в PowerPoint — сегодня это ловит только человек
  на приёмке.
- Официальный скилл `document-skills:pptx` закрывает ровно недостающее:
  программные проверки пакета (переоткрытие, rels, счёт слайдов,
  leftover-placeholder), бюджет текста `len ≤ orig_len × 1.1`, рендер-гейт,
  чек-лист подводных камней pptxgenjs. Переносим это в конвейер.
- Затем конвейер упаковывается в собственный скилл **rehau-deck** —
  заточенный под REHAU (шаблон владельца, токены брендбука, ru-RU), чего у
  универсального скилла нет. Универсальный `document-skills:pptx` остаётся
  для дек «с нуля» без шаблона (прецедент запроса — «Эволюция AI-агентов»).

## 3. Целевая схема конвейера

```
контент ──► сборка ──► verify ──► превью ──► (опц.) судья ──► сдача
             │            │          │
   build_final.py    verify_pptx.py  make_preview.py
   (шаблон, 12 сл.)  (переоткрытие,  (soffice → pdf →
   build-pptx.js     rels, счёт,      pdftoppm → PNG)
   (pptxgenjs)       placeholder,
                     бюджет)
```

- Все новые файлы — в `Презентация/harness-assets/` (папка уже в git,
  `node_modules/` игнорируется — гигиена сохраняется).
- `verify_pptx.py` работает с любой декой (переоткрытие, rels, счёт,
  placeholder-мусор); бюджет текста применим только к декам на шаблоне, где
  есть манифест (§4).
- Проверки — по практике официального скилла, переформулированные
  собственными словами (текст скилла proprietary — дословно не копируется).

## 4. Фазы и критерии приёмки

### Фаза A — verify-гейт

- Новые файлы: `verify_pptx.py`, `template-inventory.json`, `README-QA.md`.
- `verify_pptx.py`, два режима:
  - `--inventory <template.pptx>` — один раз снять манифест шаблона:
    `slide_idx, shape_name, w_cm, h_cm, font_pt, orig_len` (обход в GROUP —
    рекурсия); результат — `template-inventory.json` (коммитится);
  - `--verify <deck.pptx>` — проверки: (1) файл переоткрывается
    `Presentation()`, обход всех шейпов; (2) каждый `r:embed`/`r:link`
    слайдов резолвится в часть с непустым blob; (3) число слайдов ==
    ожидаемому (по умолчанию 12 — длина `ORDER`); (4) grep slide-XML на
    `TODO`, `xxx`, `lorem`, `[insert`, `Click to add`; (5) для дек на
    шаблоне — бюджет: фактическая длина текста шейпа ≤ `orig_len × 1.1` из
    манифеста. Находки — таблицей, код возврата ≠ 0.
- `README-QA.md` — чек-лист pptxgenjs-подводных камней своими словами:
  мутация объектов опций (фабрики — прецедент `sh()` в `build-pptx.js:24`),
  `<a:pPr>` на каждый run в rich-text массивах, `#` и 8-символьный hex,
  `outEnd` на stacked-диаграммах, `breakLine: true` между элементами,
  явный `LAYOUT_WIDE`; плюс порядок сдачи: build → verify → preview →
  (опц.) judge → владелец.
- Критерий: `--verify` зелёный на `harness-deck-v2.pptx` (12 слайдов);
  намеренно испорченная копия (удалённая media-часть при живом `r:embed`)
  ловится с внятным отчётом; прогон на чистой `base12.pptx` — 0 находок.

### Фаза B — рендер-гейт

- Предусловие (G2-pre): LibreOffice установлен — owner-действие
  `winget install TheDocumentFoundation.LibreOffice` (несколько сотен МБ).
- Новый файл: `make_preview.py` — `soffice --headless --convert-to pdf
  --outdir preview/ <deck>` → рендер PDF→PNG через **PyMuPDF** (`fitz`,
  dpi 90) → `preview/slide-NN.png`; авто-поиск soffice
  (`C:\Program Files\LibreOffice\program\soffice.exe`), при отсутствии —
  внятная ошибка с командой установки. Поправка 2026-09-14 (G2-pre
  проверен): pdftoppm в системе нет, PyMuPDF 1.28 установлен — рендер
  делаем им; конвертация soffice проверена на `harness-deck-v2.pptx`
  (13 страниц, ~5 с).
- В `README-QA.md` фиксируется известная проблема: LibreOffice подменяет
  отсутствующие шрифты (прецедент `compare-font.png`), вердикты об
  оверфлоу по превью — ориентировочные; канон оверфлоу — программный бюджет
  фазы A; финальная приёмка шрифтов — владельцем в PowerPoint.
- Критерий: `preview/slide-01..12.png` из `harness-deck-v2.pptx` получены
  одной командой; владелец подтвердил читаемость превью.

### Фаза C — скилл rehau-deck

- Файлы: `build_final.py` (+argparse: `--template --base --out --assets`,
  дефолты = текущие значения — запуск без аргументов не меняется);
  `Презентация/harness-assets/skill/SKILL.md` (frontmatter `name` +
  `description`; description настроен на триггер «презентация в стиле REHAU /
  на шаблоне владельца / дека по брендбуку») и `reference.md` —
  **генерируется из канона брендбука**
  `Презентация/harness-assets/brand/tokens.json` (план
  [2026-09-14-brand-canon-plan.md](2026-09-14-brand-canon-plan.md), фаза D;
  ручной набор токенов исключён — прежний список
  `1D1D1B / 6E6E73 / F5F5F6` отозван ревью 2026-09-14); плюс правило
  кавычек «…» для русских текстов, avoid-list «AI-look» своими словами,
  роли слайдов шаблона и `ORDER`;
  `install-skill.cmd` — копирование канона в
  `C:\Users\Admin\.agents\skills\rehau-deck\`.
- Workflow скилла: роль слайда → клон из шаблона → текст в бюджете → build →
  verify → preview → (опц.) judge → сдача; инвентаризация шаблона до
  контента, проверки после — по §4 фазы A.
- Критерии: в новой сессии скилл виден и триггерится на профильный запрос;
  мини-задача «3 слайда из шаблона (титул, шаг, финал)» проходит end-to-end
  build → verify → preview; универсальный `document-skills:pptx` не тронут
  и продолжает откликаться на прочие запросы.
- Предусловие (правка 2026-09-14): фазы A–B плана
  [2026-09-14-brand-canon-plan.md](2026-09-14-brand-canon-plan.md)
  выполнены — канон токенов и бренд-чеки существуют, reference.md
  генерируется из них.

## 6. Что не меняется / не-цели

- Продуктовый код C#/WPF, state ownership, формат `.smc`, инварианты R1–R6 —
  не затрагиваются; handover каждой фазы фиксирует «state ownership
  без изменений».
- Рабочий шаблон владельца — только чтение; содержимое слайдов деки не
  меняется.
- `build-pptx.js` не переписывается (фиксация его камней — в `README-QA.md`);
  HTML-дека `harness-deck.html` остаётся вне QA-контура (не-цель v1).
- Гигиена git: `node_modules/`, тяжёлые превью — вне коммитов, как сейчас.
- Не-цели v1: judge-субагент как обязательный шаг (остаётся опцией),
  автопочинка найденных дефектов (verify только репортит), замена
  универсального скилла.

## 7. Риски

| Риск | Митигация |
|---|---|
| LibreOffice подменяет шрифты — ложные вердикты об оверфлоу | канон оверфлоу — программный бюджет (фаза A); рендер — для грубых дефектов вёрстки; шрифты деки — Office-доступные с запасом ~10%; финальная приёмка — в PowerPoint |
| soffice недоступен / нестандартный путь | авто-поиск стандартного пути установки + внятная ошибка с командой `winget install` |
| Ложные срабатывания бюджета | бюджет — по фактическому манифесту шаблона (`orig_len`), не по формулам ширины/высоты; порог ×1.1 |
| Кириллические пути (`Презентация/`) в subprocess | пути через `pathlib`/`sys.argv`, проверка на реальной папке в критериях фаз |
| Дрейф скилла от канона | канон в репо (решение №2A), установка копированием, сверка при каждом изменении — критерий фазы C |
| Триггер-шум скилла | description узкий (REHAU/шаблон владельца); универсальный скилл остаётся для прочих запросов |

## 9. Эффект

- Дека уходит владельцу только после гейтов: программная проверка пакета →
  рендер-превью → (опц.) судья. «Восстановление файла» в PowerPoint
  становится ловимым до сдачи, а не на приёмке.
- Знания официального скилла (бюджеты, чек-листы, порядок сдачи) закреплены
  в репозитории и переживают смену инструмента.
- rehau-deck: новая фирменная презентация — одна команда вместо
  восстановления контекста скриптов; правила брендбука зашиты в скилл.
