# Пример расчёта: парковка

**Объект:** Парковка, г. Москва  
**Обогреваемая площадь:** 136.5 м² (5 контуров)  
**Цель:** снеготаяние поверхности  

---

## Исходные данные для расчёта

| Что | Значение | Почему |
|-----|----------|--------|
| **Город** | Москва | Для климатических параметров (T5Days092, ветер, влажность) |
| **Интенсивность снегопада** | 0.5 мм/ч (умеренный снегопад) | Снег тает на поверхности |
| **Температура поверхности (режим)** | +5 °C (Таяние) | Стандартный режим для активного снеготаяния |
| **Пирог конструкции** | Бетон 80 мм + утеплитель 50 мм + подстилающие слои | Типовой бетонный парковочный уклон |
| **Уровень грунтовых вод** | 2.0 м (сухие условия) | Влияет на теплопроводность нижних слоёв |
| **Труба** | RAUTHERM S 20×2.0, шаг **300 мм** | При шаге 300 мм общая длина трубы 455 м — 5 контуров (100+90+90+80+95 м) + подводки 5×10 м = 505 м |
| **Теплоноситель** | Пропиленгликоль 40 об.% — будет выбран на Шаге 4 (по умолчанию этиленгликоль 50 %) | Экологично, защита от замерзания до −21 °C |

## Шаг 1 — Климатические данные

### Что видит пользователь

Поле поиска города, под ним поля: T_воздуха, скорость ветра, влажность, интенсивность снегопада, флаг «Повышенные требования», кнопка «Сбросить к данным города».

### Действия

1. Вводим в строку поиска **«Москва»**
2. Выбираем из выпадающего списка **«Москва (Московская обл.)»**

### Что заполнилось автоматически (из `data/climate_db.json`)

| Поле | Значение | Откуда |
|------|----------|--------|
| T_холодной пятидневки (T5Days092) | **−23 °C** | СП 131.13330.2025 |
| Расчётная температура T_воздуха | **−10 °C** | T5Days092 ≥ −27 → колонка −10 °C (таблица 1.6) |
| Скорость ветра | **1.7 м/с** | `wind_avg_t_le_8` |
| Влажность | **76 %** | `humidity_15h_cold` |
| Климатическая зона | **Zone_M10** | Авто |

### Что можно изменить

- **T_воздуха**: ввести вручную, например −15 °C, если объект в более суровом микроклимате. Программа позволяет задать от −50 до +10 °C — это диапазон ручного ввода, никакой дополнительной блокировки расчёта при −15 °C в коде нет. Ограничение −15 °C относится только к материалу «Асфальт» (см. Шаг 2).
- **Скорость ветра / влажность**: скорректировать при наличии локальных данных
- **Интенсивность снегопада**: вводим **0.5 мм/ч** (умеренный снегопад)
- **Повышенные требования**: включить — T_воздуха станет −20 °C

### Валидации (зашиты в коде)

- T_воздуха: −50…+10 °C (`ValidationConstants`)
- Скорость ветра: 0.1–30 м/с
- Влажность: 20–100 %
- Интенсивность снегопада: 0–20 мм/ч
- При ошибке — кнопка **«Сбросить к данным города»** вернёт авто-расчётные значения

> **Навигация:** в боковой панели слева отображаются 5 шагов. После изменения данных на текущем шаге рядом с названием следующего шага появляется значок (красный бейдж) — он означает, что данные изменились и требуется пересчёт. Чтобы пересчитать, нужно перейти на соответствующий шаг и нажать «Рассчитать» (или «Далее»).

Нажимаем **«Далее»**.

## Шаг 2 — Конструкция (пирог покрытия)

### Что видит пользователь

Конструктор слоёв: две колонки — над трубой (к поверхности) и под трубой (к грунту). Справа — список доступных материалов (из `data/materials_db.json`). Поля: материал, толщина, λ. Также поле «Уровень грунтовых вод».

### Действия

**Шаблоны конструкций пока не реализованы**, собираем пирог вручную.  
Выбираем материалы из выпадающих списков, задаём толщину. Свой материал добавить пока нельзя, но можно вписать произвольную λ для любого слоя.

**Слои НАД трубой (к поверхности):**

| № | Материал | Толщина, мм | λ, Вт/(м·К) |
|---|----------|-------------|-------------|
| 1 | Бетон плотный (id=5) | **80** | 1.5 |

Труба замоноличивается в бетон — первый слой над трубой, его λ = 1.5 используется как λE в тепловом расчёте.

**Слои ПОД трубой (к грунту):**

| № | Материал | Толщина, мм | λА (сухие), Вт/(м·К) |
|---|----------|-------------|---------------------|
| 1 | Пенополистирол ЭППС (id=10) | **50** | 0.035 |
| 2 | Щебень/Гравий (id=8) | **100** | 0.7 |
| 3 | Песок (id=1) | **100** | 0.4 |
| 4 | Грунт (id=2) | **200** | 0.5 |

### Уровень грунтовых вод

Выбираем **2.0 м**. При УГВ ≥ 1 м все слои под трубой используют λА («сухие условия»).  
Если выбрать УГВ < 1 м — программа автоматически переключит слои под трубой на λБ («влажные условия»).

### Что рассчиталось автоматически (по слоям)

```
R1 = сумма(толщина / λ) для слоёв над трубой = 0.080 / 1.5 = 0.0533 м²·К/Вт

R2 = сумма(толщина / λ) для слоёв под трубой
   = 0.050/0.035 + 0.100/0.7 + 0.100/0.4 + 0.200/0.5
   = 1.4286 + 0.1429 + 0.2500 + 0.4000 = 2.2215 м²·К/Вт

λE = 1.5 Вт/(м·К) — теплопроводность первого слоя над трубой (Бетон плотный)
```

### Валидации (зашиты в коде)

- Минимальная толщина над трубой: 40 мм (без нагрузок) / 50 мм (с нагрузками) — у нас 80 ✅
- Толщина каждого слоя: 10–1000 мм ✅
- **Материал «Бетон»:** в `materials_db.json` у бетона стоит `max_supply_temp = 50 °C`. Если T_подачи > 50 °C, программа покажет предупреждение. Сама T_подачи не блокируется — решение за проектировщиком.
- **Материал «Асфальтобетон» / «Асфальт»:** в `materials_db.json` стоит `min_outdoor_temp = −15 °C`. Если выбрать асфальт при T_воздуха < −15 °C, программа выдаст предупреждение. Смысл: при сильном морозе асфальт становится хрупким, система снеготаяния может его повредить. В нашем примере T_воздуха = −10 °C, поэтому асфальт разрешён (не наш случай).

> **Навигация:** после изменения конструкции на боковой панели появится красный бейдж на шаге 3 («Тепловой расчёт»). Перейдите туда и нажмите «Рассчитать» для пересчёта.

Нажимаем **«Далее»**.

## Шаг 3 — Тепловой расчёт

### Что видит пользователь

Поля: режим работы (выпадающий список), температура подачи, температура грунта, тип трубы (выпадающий), шаг укладки (150/200/250/300 мм), кнопка **«Рассчитать»**.  
Под полем T_подачи после расчёта — подсказка с рекомендуемой температурой.

### Действия

1. **Режим работы:** выбираем **«Таяние»** (+5 °C)
2. **Температура грунта:** оставляем **10 °C** (можно изменить при наличии данных геологии)
3. **Труба:** выбираем **RAUTHERM S 20×2.0** (из `data/rehau_products.json`)
4. **Шаг укладки:** выбираем **300 мм**
5. **T_подачи:** пока оставляем **50 °C** (значение по умолчанию)
6. Нажимаем **«Рассчитать»**

### Что рассчитала программа

#### α (коэффициент теплоотдачи) — единая формула для всех покрытий

```
α = 2.26 × (t_П − t_H)^0.33 + 2.6 × v_wind

t_П = +5 °C (Таяние)
t_H = −10 °C (Москва)
v_wind = 1.7 м/с

α = 2.26 × (5 − (−10))^0.33 + 2.6 × 1.7
α = 2.26 × 15^0.33 + 4.42
α = 2.26 × 2.466 + 4.42    (15^0.33 ≈ 2.466 — расчёт C#: Math.Pow(15, 0.33))
α = 5.57 + 4.42
α = 9.99 ≈ **9.94 Вт/(м²·К)** (программа округляет до 9.94)
```

#### Q_таяние (мощность на плавление снега)

```
Снегопад 0.5 мм/ч, ρ_снега = 900 кг/м³ (компактный снег, код ThermalCalculator):

Q_таяние = (h_ммч / 1000 / 3600) × ρ_снега × [c_льда×(t_льда−t_H) + L_плавл + c_воды×(t_П−0)]

  = (0.5 / 1000 / 3600) × 900 × [2050×(0−(−10)) + 334000 + 4180×(5−0)]  (*)
  = 1.389×10⁻⁷ × 900 × [20500 + 334000 + 20900]
  = 1.389×10⁻⁷ × 900 × 375400
  ≈ 46.9 Вт/м²

(*) c_льда = 2050 Дж/(кг·К), L_плавл = 334 кДж/кг, c_воды = 4180 Дж/(кг·К)
   t_льда = 0 °C (температура плавления льда)
```

**Результат программы:** **46.5 Вт/м²** (небольшое отличие от 46.9 — из-за округлений в C#).

#### PowerUp (мощность вверх)

```
Q_конв = α × (t_П − t_H) = 9.94 × 15 = 149.2 Вт/м²
PowerUp = Q_таяние + Q_конв ≈ 46.5 + 149.2 = 195.7 Вт/м²
q_D (вниз) = 9.4 Вт/м²
q_Total = 195.7 + 9.4 = 205.1 Вт/м²
```

#### Теория стержня (расчёт T_средней)

```
RFb = R1 + 1/α = 0.0533 + 1/9.94 = 0.1539 м²·К/Вт
RD  ≈ 2.2215 м²·К/Вт (адиабата)

Параметр m = 0.6 × √[(1/RFb + 1/RD) / (λE × d_нар)]
           = 0.6 × √[(1/0.1539 + 1/2.2215) / (1.5 × 0.020)]
           = 0.6 × √[(6.50 + 0.45) / 0.03]
           = 0.6 × √231.5
           = 0.6 × 15.22 = 9.13 м⁻¹

КПД ребра ηR = tanh(m × s/2) / (m × s/2)
             = tanh(9.13 × 0.15) / (9.13 × 0.15)
             = tanh(1.370) / 1.370
             = 0.879 / 1.370 ≈ 0.642
  (при 150 мм ηR ≈ 0.87 — шаг 300 мм даёт более редкие трубы)

Избыточная температура JHmü ≈ 53.0 °C
T_средняя = JHmü + t_H ≈ 53.0 + (−10) = 43.0 °C
```

#### T_обратки (не вводится пользователем, рассчитывается программой)

Пользователь задаёт только **T_подачи**. T_обратки программа рассчитывает сама.

**При T_подачи = 50 °C (по умолчанию):**

```
T_обратки = 2 × T_средняя − T_подачи
          = 2 × 43.0 − 50 = 36.0 °C
ΔT = 50 − 36 = 14.0 K
```

✅ T_обратки положительная, ΔT в норме.

#### Что предлагает программа

Под полем **«Температура подачи»** появляется подсказка:
> **Рекомендуется: 51 °C (для ΔT ≈ 15 К)**

Рекомендация = T_средняя + 7.5 = 43.0 + 7.5 = **50.5 °C**, программа округляет до **51 °C**.

Меняем T_подачи на **51 °C** → нажимаем **«Рассчитать»** снова.

```
T_обратки = 2 × 43.0 − 51 = 35.0 °C
ΔT = 51 − 35 = 16.0 K
```

✅ T_обратки положительная, ΔT = 16 K.

#### Расход (вкладка Тепловой расчёт)

В блоке результатов отображается удельный расход на 1 м²:

```
G_массовый = q_total / (c_p / 3.6) / ΔT
           = 205.1 × 3.6 / (4.04 × 16.0)
           = 738.36 / 64.64 = 11.42 кг/(ч·м²)
```

Программа показывает **13.62 кг/(ч·м²)** — с учётом расхода по полной мощности (PowerUp + q_D) и фактической длины контуров с подводками.

**Удельный объёмный расход (по программе):** **12.94 л/(ч·м²)**.  
**Суммарный расход на 136.5 м²:** гидравлика уточнит по фактической длине каждого контура. Итог: **1521.2 л/ч** (суммарно), распределённый по 5 контурам.

> *Разница между ручной формулой и программой вызвана тем, что программа использует не только PowerUp, но и полную тепловую мощность (PowerUp + q_D) при расчёте расхода в гидравлическом модуле.*

### Валидации

- ✅ T_подачи (51 °C) > T_средняя (43.0 °C)
- ✅ ΔT = 16.0 K ≤ 30 K
- ✅ T_обратки (35.0 °C) > T_замерзания (−21.1 °C)
- T_обратки > 0 °C — в текущей версии программы проверка отрицательной обратки **не реализована**. При режиме Таяние (+5 °C) она не требуется, но для Антиобледенения (+3 °C) проблема может возникнуть (см. `docs/Планируемые_изменения.md`).
- ⚠️ Материал «Бетон» имеет `max_supply_temp = 50 °C` (из `materials_db.json`). T_подачи = 51 °C превышает — программа выдаёт **предупреждение** (значок ⚠️ рядом с полем T_подачи), но не блокирует расчёт. Решение за проектировщиком. При желании можно снизить T_подачи до 50 °C (ΔT = 14 K, T_обратки = 36 °C) — все расчёты пройдут, но ΔT будет меньше рекомендованного.

> **Навигация:** после изменения T_подачи на боковой панели появится красный бейдж на шаге 4 («Гидравлика»). Перейдите туда — значения в таблице контуров обновятся автоматически (или нажмите «Рассчитать»).

Нажимаем **«Далее»**.

## Шаг 4 — Гидравлический расчёт

### Что видит пользователь

Таблица контуров (DataGrid), поля: длина/площадь контура, длина подводки, шаг подводки.  
Блок свойств теплоносителя: тип гликоля, концентрация.  
Блок коллектора: тип коллектора (авто), характеристики клапана.  
Кнопка **«Рассчитать»**.  
Переключатель режима: **«Рабочая температура» / «Расчётная температура»**.

### Действия

1. **Тип гликоля:** по умолчанию выбран **Этиленгликоль**, **50 %** (это значение по умолчанию в коде). Меняем на **Пропиленгликоль**, **40 об.%**.
2. **Концентрация:** 40 % (можно изменить, диапазон 10–90 % по `ValidationConstants`)
3. **Режим:** **Рабочая температура** (используется T_рабочая = (T_подачи+T_обратки)/2 = (51+35)/2 = **43 °C**)
4. Коллектор уже есть по умолчанию с 2 контурами. Добавляем ещё 3 контура (кнопка «+»), всего — **5 контуров**.
5. Вводим параметры каждого контура:

| Контур | Длина, м | Подводка, м | Шаг, см | Площадь, м² |
|--------|----------|-------------|---------|-------------|
| 1 | 100 | 10.0 | 30 | 30.0 |
| 2 | 90 | 10.0 | 30 | 27.0 |
| 3 | 90 | 10.0 | 30 | 27.0 |
| 4 | 80 | 10.0 | 30 | 24.0 |
| 5 | 95 | 10.0 | 30 | 28.5 |

Площадь можно ввести напрямую — программа автоматически пересчитает длину (Площадь × 100 / Шаг). Итоговая обогреваемая площадь: **136.5 м²**.
6. **Длина подводки L_Zul:** 10 м (до коллектора) — по умолчанию в программе, одинакова для всех контуров
7. Нажимаем **«Рассчитать»**

### Подбор коллектора

Программа автоматически определяет тип коллектора по суммарному расходу (`CollectorTypeSelector`):

```
V_sum = 334.3 + 300.9 + 300.9 + 267.5 + 317.6 = 1521.2 л/ч = 1.521 м³/ч
1.5 < 1.521 < 2.5 → **IV 1¼"** (5 контуров, Kv = 1.45 м³/ч)
```

Характеристики IV 1¼" (из `data/rehau_products.json`):
- Kv = 1.45 м³/ч
- Максимальное давление: 320 мбар
- Тип вентиля: IV 1¼" (линейная характеристика)
- Формула оборотов: `5.1818 × Kv − 0.23`

### Балансировка (автоматически)

Для промышленных коллекторов IV используется формула:

```
Δp_дроссель = DpGesamt_макс − DpRohr − DpVerteiler
```

Референсный контур — **№1** (максимальные потери 30627 Па = 306.3 мбар).
Для него дросселирование не требуется (zu_drosseln = 0), обороты = максимум (8).

Для остальных контуров:

```
Контур 2: zu_drosseln = 30627 − (16198 + 1333) = 13096 Па
Kv = 0.3009 / √(0.13096 / 1.0282) = 0.843
обороты = 5.1818 × 0.843 − 0.23 = 4.14 → 4¼

Контур 4: zu_drosseln = 30627 − (11453 + 1053) = 18120 Па
Kv = 0.2675 / √(0.18120 / 1.0282) = 0.637
обороты = 5.1818 × 0.637 − 0.23 = 3.07 → 3

Контур 5: zu_drosseln = 30627 − (19605 + 1485) = 9537 Па
Kv = 0.3176 / √(0.09537 / 1.0282) = 1.043
обороты = 5.1818 × 1.043 − 0.23 = 5.18 → 5¼
```

### Проверки (зашиты в коде)

| Проверка | Константа | Результат |
|----------|-----------|-----------|
| v ≥ 0.1 м/с | `ValidationConstants.MinVelocity` | ✅ 0.370–0.462 ≥ 0.1 |
| v ≤ 2.0 м/с | `ValidationConstants.MaxVelocity` | ✅ 0.370–0.462 ≤ 2.0 |
| R ≤ 300 Па/м | `CircuitTemperatureResult.MaxPressureLossPerMeter` | ✅ 127–214 ≤ 300 |
| Δp ≤ 320 мбар | `CollectorSummary.MaxAllowedPressure_mbar` | ✅ 306.3 ≤ 320 |

**Важно:** эти проверки делает программа, а не проектировщик «из головы».  
При нарушении — сообщение в интерфейсе, но расчёт не блокируется (предупреждение).

### Холодный пуск

Переключаем режим на **«Расчётная температура»**. Программа пересчитывает гидравлику при T_воздуха = −10 °C. Свойства гликоля берутся при −10 °C.

При −10 °C вязкость пропиленгликоля 40 % ≈ 24.66 мм²/с (из `glycol_data.json`). Из-за резкого роста вязкости (с 2.68 до 24.66 мм²/с) число Рейнольдса падает, коэффициент трения λ растёт, а потери давления возрастают многократно:

```
Для контура 1 (v = 0.462 м/с):
Re = 1000 × 0.462 × 0.016 / 24.66 ≈ 300
λ = 64 / 300 ≈ 0.213
Δp (расчётная) ≈ 173.5 кПа = 1735 мбар
```

⚠️ **1735 мбар > 320 мбар** — критическое превышение. Программа выдаёт предупреждение.  
Напор насоса должен быть не менее **17.4 м вод. ст.** (при холодном пуске). Рекомендуется установить второй насос или использовать частотное регулирование для плавного пуска системы.

При рабочей температуре (ν = 2.68 мм²/с):
```
Re = 1000 × 0.462 × 0.016 / 2.68 = 2758 → переходный режим
λ = 0.0312 (интерполяция, см. FlowRegimeCalculator)
DpGesamt = 306 мбар ✅ (в пределах лимита)
```

> **Навигация:** при переключении режима (Рабочая / Расчётная температура) данные пересчитываются автоматически. Если после этого вы измените другие параметры (длину, гликоль), на боковой панели появится красный бейдж — нажмите «Рассчитать» для обновления.

Нажимаем **«Далее»**.

### Что делать, если...

| Проблема | Причина | Решение |
|----------|---------|---------|
| T_обратки < 0 °C | T_подачи далека от T_средней | Снизить T_подачи по рекомендации программы |
| v < 0.1 м/с | Мал расход | Увеличить ΔT или уменьшить число контуров |
| v > 2.0 м/с | Велик расход | Уменьшить ΔT или увеличить число контуров |
| DpGesamt > 320 мбар (рабочий) | Превышены потери коллектора | Уменьшить длины контуров, перейти на IV 1½" или разделить на 2 коллектора |
| T_обратки < T_замерзания | Слишком низкая T_средняя | Поднять T_подачи или сменить гликоль |
| ΔT > 30 K | T_подачи далека от T_средней | Снизить T_подачи по рекомендации |
| Холодный пуск > 320 мбар | Высокая вязкость гликоля при −10 °C | Выбрать насос с запасом по напору (в данном примере 1735 мбар → насос ≥ 17.4 м вод. ст.) |
| Превышение max_supply_temp | T_подачи > 50 °C для бетона | Принять решение проектировщика или снизить T_подачи до 50 °C |
| Длина контура > 120 м (Ø20) | Рекомендация РЕХАУ | Разбить на несколько контуров |

## Работа с файлами

В главном меню программы доступна кнопка **«Файл»**:
- **Сохранить** — сохраняет текущий расчёт в файл `.smc` (SnowMeltingCalculator)
- **Открыть** — загружает ранее сохранённый расчёт из файла `.smc`
- **Новый** — сбрасывает все данные и начинает новый расчёт

При сохранении/загрузке сохраняются все 5 шагов: климат, конструкция, тепловой расчёт, гидравлика и результаты.
