# Baseline test protection

## Scope and protection rules

This audit records current protection without changing product code, tests, tolerances, or the numeric fixture. The immutable numeric source is `tests/SnowMeltingCalculator.Tests/baseline_refactor_dedupe.json`; TRX files record only test outcomes.

Protection classifications are deliberately strict:

- **NumericFixture**: an executed baseline case serializes and directly compares the named output field. This protects the end-to-end number for the fixture inputs, not every intermediate or branch that contributes to it.
- **Behavioral**: an existing focused test asserts the branch or outcome, but the JSON fixture does not serialize a distinguishing numeric field for it.
- **None**: no concrete fixture field or focused test was found that distinguishes the formula or branch. Green selected suites do not upgrade this classification.

The selected run executed 68 thermal tests and 69 hydraulic tests with zero failures. Fixture integrity and exact counts are recorded in `.omo/evidence/phase-1/task-6-baseline-summary.md`.

## Missing serialized result fields

The thermal fixture omits `RFb`, `RD`, `ParameterM`, `EfficiencyEtaR`, `MeltingHeat`, `RadiationHeat`, `ConvectionHeat`, `IsValid`, and `ValidationErrors`. It also cannot serialize private PowerDown intermediates (`jhmuLow`, `A`-`E`, numerator, denominator). Therefore a passing `ThermalOutput_MatchesBaseline` does not prove those values or branches independently.

The circuit fixture omits balancing and collector outputs including `IsReferenceCircuit`, `Throttling`, `ValveTurns`, `ValveTurnsWarning`, collector totals, reference circuit number, warnings, and validity. The serialized `zuDrosseln` field is zero in every case and is not evidence that `CalculateBalancing` ran.

## Mandatory Phase 2 gap list

1. Thermal invalid-input, insufficient-supply, negative-PowerDown and exception early returns need field-by-field calculated versus `NotCalculatedDefault` characterization.
2. Thermal `RFb`, `RD`, rod values, heat components and private PowerDown intermediates need direct numeric protection before extraction or details-model refactoring.
3. Hydraulic fixture needs `IV_1_5`, water, propylene and multiple-circuit cases; current fixture contains only `HKV_D`/`IV_1_25` with ethylene 30/50%.
4. Balancing and collector calculations need immutable multi-circuit numeric characterization; current fixture never invokes those methods.
5. Interpolation needs exact-grid, temperature-only, concentration-only, bilinear, boundary, NaN and data-fallback characterization in the selected Phase 2 protection suite.
6. Valve forward/inverse formulas, quarter rounding, max warnings, Newton termination and clamps need selected numeric characterization.
7. Exact Reynolds boundaries and iterative friction internals need focused characterization; sampled final fixture outputs are insufficient branch proof.

## Audit conclusion

The selected suites are green and the fixture hash is stable, but protection is intentionally classified as partial. Product refactoring must not treat green suite status as full formula coverage; Critical and High gaps above are Phase 2 test-protection prerequisites.
