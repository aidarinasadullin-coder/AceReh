## Полный отчёт ревьюера (дословно)

**1) VERDICT: APPROVE-WITH-EDITS**

**2) REASON:** Инварианты R1–R6, wire `.smc` и writers не задеты — план правит
только тестовый проект, `ArchitectureRulesTests` не ссылается на целевой файл,
characterization фазы 10 (`Services/Project/`) вне поверхности разрезки. Якоря
«файл:строка» волны A сверены (20+ из 20+ сходятся), owner-решения V1–V4
планом не присвоены сверх полученных. Но партиция неполна: 4 живых теста не
попали ни в одну волну; «645 строк» F5-теста — артефакт диапазона, включающий
~470 строк общих фабрик, из-за чего метрика успеха −850…−900 недостижима;
механизм разделения общих фабрик противоречит сам себе (§1 «по темам» vs §5
«по использованию» — граф вызовов кросс-темный). Реализация «как написано»
соберётся (сборка поймает), но дифф выйдет за границы, описанные планом, и
метрика провалится.

**3) FINDINGS:**

1. **P1 (A2 — полнота партиции).** 4 теста не упомянуты ни в одной волне A/B/C:
   `Session_IdentityChangedExternally_ViewModelRepostsToHeader`
   (`ResultsViewModelOpenProjectTests.cs:66`), и три
   `[Category("PersistenceFailure")]` — `:2936`, `:3023`, `:3094`. При этом §0
   называет «отказоустойчивость persistence» одной из пяти тем файла.
   Доказательство намерения: заявленный объём файла 3 «~550 строк» сходится
   только с учётом этих трёх (6 перечисленных ≈ 354 строки, +202 строки блока
   :2934–3137 ≈ 556). Правка: явно включить 3 PersistenceFailure-теста в
   `ResultsViewModelSaveSnapshotTests.cs` (9 тестов, не 6), а
   `Session_Identity…` — в restore-файл; иначе ревью диффа зафиксирует перенос
   тестов в файлы, которых нет в плане.

2. **P1 (A1/A5 — завышенный F5, битая метрика).** «:1672–2316, 645 строк» —
   диапазон до `[Test]` следующего теста; реальный F5-метод — `:1672–1799`
   (128 строк) + doc-комментарий `:1662–1670`, итого **~138 строк**, из них
   21 assert из 302 по файлу. Строки 1801–2314 — рефлексия-хелперы
   (1801–1844) и блок общих фабрик (1847–2314), нужные 43 выжившим тестам и
   неудаляемые. Следствия: (а) §6 «−850…−900», «62 154 → ~61 300»
   недостижимы — после всех волн реально ~−300…−400; (б) собственная
   арифметика плана противоречива: 250+740+550+820+430 = 2790 > 3249−645 =
   2604. Правка: заменить 645 → ~138, пересчитать метрику успеха (строчная
   экономия — вторичная метрика).

3. **P1 (A3 — механизм разделения фабрик не specified и противоречив).** §1:
   «фабрики `Create*` делятся по темам»; §5: «делятся по фактическому
   использованию». Фактический граф кросс-темен: `CreateCircuitsViewModel`/
   `CreateClimateViewModel`/`CreateConstructionViewModel` и цепочка
   `CreateViewModel` (5 перегрузок, :1854–1911, :2092) зовутся всеми 5 темами;
   `CreateThermalViewModel` — четырьмя; `GetField<T>` (:2309) — файлами 2, 3, 4
   (:2493, :2917, :1024); `CreateInitializedConstructionViewModelAsync`
   (:1847) — round-trip-файлом и кластером волны C; константа `TestFilePath`
   (:53) нужна файлам 1 и 3. Без дублирования «по темам» не делится; с
   дублированием файл 2 ≈ 1100+ строк и ломается пин «максимум ≤ ~950».
   Правка: один внутренний общий static-класс фабрик (6-й артефакт).

4. **P2 (A5/A6 — счётчик тестов).** §0 «45 тестов», §6 «45 → 44» — фактически
   **44** `[Test]`, после V2(а) — 43.

5. **P2 (A7 — единица grep-пина).** Пин «счётчик `Assert\.` по файлу не
   уменьшается» не определён после разрезки и ложен для цикла A+B. Правка:
   «сумма `Assert\.` по 5 новым файлам ≥ 281 (= 302 исходного файла − 21 F5);
   состав имён тестов меняется только по V2(а)». Пин «Assert.Ignore → 0»

6. **P2 (A2 — размещение кластера волны C при разрезке).** Пять тестов

7. **P3 (A5 — мелкие счётчики).** «21 файл с инлайнами `new ProjectData`» —
