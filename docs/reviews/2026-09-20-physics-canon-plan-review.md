## Имплементационные находки (закрытие находки №2, прогон 2026-09-20)

Переходный пин «JSON == fallback» поймал **фактический дрейф fallback-таблиц пропиленгликоля**: строки 50/60/70% плотности были переписаны со сдвигом на одну строку концентрации относительно канона (в fallback 50% при −17.8°C стояло 1073.6 — значение JSON для 40%; канон: 40%→1073.6, 50%→1083.2, 60%→1081.6). Гидравлика при битой поставке считала по смещённым плотностям. Закрыто перегенерацией всех 8 fallback-массивов из узлов JSON-канона (`GlycolDataService.cs`, эталон — data/glycol_data.json; штатный JSON-путь расчёта не менялся ни на бит — базлайн-тесты зелёные). Дополнительно зафиксировано для владельца (правка канона — вне refactor-волны): в JSON-каноне плотность пропилена при −17.8°C немонотонна (60% → 1081.6 < 50% → 1083.2) и 70–90% пусты — вероятная аномалия исходных таблиц, проверить по ASHRAE при случае. После перегенерации пин проверяет узлы fallback-сетки (9×9, подмножество 25-точечной сетки JSON): числа — допуск D6 1e-9; fallback-NaN при JSON-числе — допускается (известная грубость сетки, см. аномалию выше); fallback-число при JSON-None — падение.

Решения owner-вопросов (§6.3 «решить на ревью»): fallback гликолевых таблиц — **оставить** (вариант A: волна refactor, режим отказа не меняется; наблюдаемость усиливается AppLog.Warn в ветке «файл не найден» + пин-тест находки №2; удаление fallback — отдельный owner-решённый hardening-пункт). XAML `ConverterParameter="32000"` — **остаются строками** (конвертер ожидает `parameter is string`; x:Static числовой константы молча вернёт UnsetValue и погасит красную индикацию); комментарии XAML/конвертера дополняются ссылкой на канон.

## 4. Рекомендации по пунктам ж и д5

**ж (гликоль-fallback) — рекомендую вариант A**, оставить fallback + добавить `AppLog.Warn` в ветку «файл не найден» (GlycolDataService.cs:401, сейчас только Debug.WriteLine). Обоснование:
1. Волна декларирует «значения НЕ меняются» — вариант B меняет режим отказа приложения (тихий fallback → исключение при старте расчёта), это behavioral change вне рамок refactor.

B не нужен для надёжности поставки: `data/glycol_data.json` копируется csproj'ом (src/SnowMeltingCalculator.csproj:41-44, `..\data\*.json` → `data\`) и реально лежит в тестовом выводе (tests/.../bin/Debug/net8.0-windows/data/glycol_data.json существует) — файл найдётся и в тестах, и в проде; битая поставка — единственный сценарий fallback.

**д5 (XAML 32000) — принимаю предложенный план: строки остаются, комментарий дополняется ссылкой на `HydraulicsConstants.MaxPressureLoss_Pa`.** Обоснование: конвертер требует `parameter is string` (src/Converters/Converters.cs:298) — `x:Static` числовой константы передаст boxed int, ветка молча вернёт UnsetValue, красная индикация превышения исчезнет безошибочно и без падения тестов (тестов на цвет ячейки нет) — это худший вид регрессии.
