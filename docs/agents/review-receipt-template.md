# Шаблон чека независимого ревью (review receipt)

> Кодификация живой практики четырёх чеков (R-2026-09-12-01,
> R-2026-09-13-01/-02/-03; план docs/plans/2026-09-12-process-gates-plan.md,
> решения 8–9, §5). Чек пишет **независимый read-only ревьюер** (subagent с
> чистым контекстом), не автор изменения. Обязателен для материальных
> изменений (state ownership, persistence, архитектурные правила, широкий
> сурфейс — как определено в AGENTS.md). ADR и коммит ссылаются на путь
> чека. Имя файла: `docs/reviews/YYYY-MM-DD-<topic>-review.md`;
> `REVIEW_ID`: `R-YYYY-MM-DD-NN` — **пишется полностью**, без тире-шорткатов
> (урок №29). Копировать блок ниже в новый файл и заполнять.

```text
REVIEW_ID: R-YYYY-MM-DD-NN
SUBJECT: <что ревьюится: план/дифф — путь + одна строка сути>
REVIEWER: независимый read-only subagent, чистый контекст (Explore)
DATE: YYYY-MM-DD
RECEIPT: настоящий файл (полный отчёт ревьюера сохранён ниже)
VERDICT: APPROVE | APPROVE-WITH-EDITS | REJECT
REASON: <2–5 строк: почему такой вердикт; инварианты R1–R6, wire .smc,
        writers — задеты или нет; реализация после owner-signal>
```

## Вектора атаки (канонический блок промпта ревью — урок №26)

```text
Роль: независимый read-only ревьюер, чистый контекст, не автор изменения.
Задача — АТАКА: найди, чем план/дифф провалится при реализации, а не
подтверди корректность. Каждый вектор — отдельный проход:
A1. Якоря «файл:строка» — каждый открыть и сверить по коду.
A2. Названные в плане поля/методы/типы — существуют ли в заявленных
    источниках (сигнатуры, снапшоты, XAML, csproj).
A3. Ripple: ctor-параметры, места конструирования в тестах, привязки
    XAML, деплой-файлы, AutomationId-контракты; существование каждого
    названного ID (REVIEW_ID/ADR/уроки) — сверить с первоисточником.
A4. Архитектура: сканы R1–R6, списки санкционированных writers,
    wire-контракт .smc.
A5. Арифметика: суммы и числа плана и show-me сходятся между собой.
A6. show-me ↔ план: сущности, подписи, реальные строки UI; токены —
    канон Tokens.Colors.xaml.
A7. Гейты: не присвоил ли план owner-решение; спорные решения —
    два варианта (A/B) с явным выбором владельца.
A8. Процесс: чек ревью существует; записи quality-log последних
    фаз на месте.
Вердикт: APPROVE | APPROVE-WITH-EDITS | REJECT + находки P0–P3 со
статусами (исправлено в диффе / отложено / отклонено владельцем).
Чек: docs/reviews/YYYY-MM-DD-<topic>-review.md.
```

Правила режима: вердикт требует находок, а не согласия; 3 ревью подряд
с 0 находок — сигнал ротации векторов (запись в
`docs/agents/quality-log.md`, урок №26). show-me сверяется с планом
обязательно (A6) — артефакт регенерируется из плана, не правится руками
(урок №27).
