# UI smoke-набор (Фаза 1Б редизайна)

FlaUI.UIA3 5.0.0 (MIT, dev-only — в дистрибутив приложения не попадает)
автоматизирует реальный exe приложения через существующие AutomationId.
Селекторный контракт закреплён
`Thermal/ThermalAutomationIdSelectorContractTests.cs`; каркасные слоты:
`ShellValidationMessage`, `ShellRecalcMessage`, `ShellModulePlate`.

## Что проверяет

| Тест | Сценарий |
|---|---|
| `StartupAndNavigationSmokeTests` | Чистый старт exe, брендированный заголовок, плашка «КЛИМАТ» в статус-баре, переход по всем 5 шагам степпера (плашка + якоря `ThermalMode`, `HydraulicsGlycolType`, `ResultsThermalPower`). |
| `ProjectFileSmokeTests` | Открытие `.smc` через командную строку (сценарий двойного клика в проводнике), правка подачи, один тепловой расчёт (сходится при реалистичном входе), сохранение через меню «Файл → Сохранить», проверка файла на диске. |

Фикстура `Fixtures/v1-sample.smc` **read-only** — не мутируется. Для сценария
сохранения тест создаёт временную копию в `%TEMP%` и приводит её климат к
реалистичному рабочему режиму (воздух −2 °C, ветер 3 м/с; в фикстуре —
расчётный холодный −28 °C/5 м/с, при котором расчёт неосуществим в принципе).

## Запуск

Требуется интерактивная Windows-сессия (UIA3 не работает в headless/службах).
Приложение должно быть собрано:

```bash
dotnet build SnowMeltingCalculator.sln
dotnet test tests/SnowMeltingCalculator.Tests/SnowMeltingCalculator.Tests.csproj --filter "Category=UiSmoke"
```

## Исключение в headless/CI

Smoke-тесты помечены `[Category("UiSmoke")]` и входят в обычный `dotnet test`.
В headless/CI-прогонах исключаются фильтром:

```bash
dotnet test --filter "Category!=UiSmoke"
```

## Замечания

- Один запуск приложения на фикстуру (`OneTimeSetUp`), процесс закрывается
  грейсфулом с принудительным `Kill`-фолбэком (`Application.Close(true)`).
- Тайминги: окно до 90 с (SelfContained-старт), UI-переходы 10 с, расчёт 30 с.
- Во время прогона окно приложения открывается на рабочем столе; мышь и
  клавиатура не используются (только UIA-паттерны: SelectionItem, Value,
  Invoke, ExpandCollapse).

## Известные ограничения (отложено, не блокируют)

Из read-only ревью Фазы 1Б (2026-09-05); за исключением первого пункта —
косметика, в объём фазы не вошли:

1. **Эвристика степпера**: `NavigateTo` берёт первый `ControlType.List` в
   дереве окна и ищет шаги в нём. Появление нового List-контрола выше по
   дереву (popup комбобокса, будущие списки) сломает навигацию. Решение —
   AutomationId на ListBox степпера, добавить в одной из следующих фаз
   редизайна вместе со строкой селекторного контракта.
2. **Порядок teardown**: `DeleteTempCopy` (производный класс) выполняется
   раньше `CloseApplication` (базовый) — temp-файл удаляется до завершения
   процесса приложения. Запись атомарная и файл не залочен, но антивирус/
   фоновая запись могут дать IOException в teardown. На будущее: виртуальный
   хук очистки в базовом классе после `App.Dispose()`.
3. **Медленный фейл при мгновенном краше exe**: `Retry.WhileNull` отрабатывает
   полные 90 с, даже если процесс уже умер. Можно досрочно прерывать по
   `app.HasExited`.
