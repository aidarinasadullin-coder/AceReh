## Scope
### Must have
- C1 Characterization test net covering current Thermal calculator numeric outputs AND current CircuitsViewModel flow results (PowerUp, FlowRate, kv, balancing), so any behavior change fails loud.
- C2 Single source for MinPipeSpacing/MaxPipeSpacing (ValidationConstants); ThermalConstants references removed.
- C3 `ThermalParameters` renamed/replaced by immutable `ThermalInputs` containing ONLY thermal-owned fields (Mode, SupplyTemperature, DeltaT, GroundTemperature, Pipe, PipeSpacing, LambdaE). Calculator signature accepts `ThermalInputs` + `IClimateData` + `IConstructionData` (NOT a flattened clone).
- C4 `ThermalCalculationResult` drops echo-in fields `Pipe`, `PipeSpacing`, `R1Total`, `R2Total`. `SupplyTemperature`/`ReturnTemperature`/`DeltaT` remain (they are computed/propagated outputs the downstream genuinely reads). All readers updated to read dropped fields from contracts.
- C5 `PipeSpacing` has ONE canonical writer = `ThermalViewModel` (via `ICalculationStateService.SetPipeSpacing`). `ConstructionViewModel` and `ResultsViewModel` are observe-only via `PipeSpacingChanged`. Unit canon = mm; all `/10.0` conversions centralized in one named helper.
- C6 `HydraulicInputData` keeps ONLY user-input fields (GlycolType, GlycolConcentration, SupplySpacing_cm, SupplyHeatPercent, ValveType). Thermal/climate fields removed; CircuitsCalculator reads them from `IThermalCalculationResult`/`IClimateData` directly.
- C7 `CalculationContext` registered as singleton in DI and consumed by `CircuitsViewModel` as the inter-module data bus (climate air-temp + thermal result) instead of sibling-VM injection. `ThermalViewModel`/`ClimateViewModel` injected into `CircuitsViewModel` removed (stringly-typed PropertyChanged handlers too).
- C8 Empty dead directory `D:\IA\ace\ViewModels\Hydraulics\` deleted; `git status` shows no orphan references.
- Every wave ends `dotnet build` green AND `dotnet test` green; characterization test values unchanged vs Wave 0 baseline.

### Must NOT have (guardrails, anti-slop, scope boundaries)
- NO change to any calculation formula or numeric constant вЂ” only data-structure shape and flow.
- NO new product features (Word/PDF export stays deferred; no new pipe types, no new materials).
- NO XAML layout / MaterialDesign theme changes (binding PATH updates allowed only where a renamed property forces it; XAML visual layout untouched).
- NO rename of public API surface consumed by installer/publish/Project serializers UNLESS the serialization DTO (`ProjectData`, `CircuitData.PipeSpacingCm`) is updated in the SAME todo to keep v1.0 project files loadable.
